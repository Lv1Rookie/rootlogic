# Checking Quotes Against Pages Beats Prompting

Almost every shipped research assistant and open-source research agent enforces citations by *asking the model nicely*, and then checks only that the citation number or URL exists — not that the page says what the sentence claims. Across the five most prominent open-source deep-research projects surveyed (gpt-researcher, STORM, LangChain `open_deep_research`, HuggingFace `open_deep_research`, Local Deep Research), **no project verifies a claim against the text of the page it cites**; the nearest thing is STORM's `clean_up_citation`, which only confirms a `[n]` marker indexes a retrieved document ([storm utils.py](https://github.com/stanford-oval/storm/blob/main/knowledge_storm/utils.py)). A grep across all four citing projects for a `quote in page_text` style assertion returns nothing. rootlogic already does both of the things that are missing: it judges each claim against the fetched page text and then confirms in code that the verifier's "verbatim" quote actually appears in that text (`rootlogic/verify.py`, `quote_in`). Where the vendors are genuinely ahead is in citation *plumbing* — Anthropic returns the supporting passage as a first-class API field and guarantees the pointer is real ([Citations](https://platform.claude.com/docs/en/build-with-claude/citations)) — and where the research literature is ahead is in *measurement*: ALCE's per-citation precision, VeriScore's verifiable/unverifiable split, and MiniCheck's 770M-parameter entailment checker that matches GPT-4 at roughly 1/400th the cost ([arXiv:2404.10774](https://arxiv.org/abs/2404.10774)). The highest-value adjustments for rootlogic are therefore cheap and deterministic: split "unverifiable" into "couldn't read the page" versus "not a checkable claim", attribute each claim's quote to a specific cited URL so citation precision becomes measurable, force numeric claims to be backed by a quote containing the number, and add the free academic-integrity signals (Retraction Watch, Unpaywall, DOAJ) as annotations rather than filters. The contested commercial credibility raters and the retired vendor confidence scores are not worth adopting at all.

## The field's verification stack is four mechanisms, and only one of them is code

**Mechanism one: attach a pointer, resolve it later.** OpenAI and the current Gemini API both return character-span annotations over the generated text — a `url_citation` with `url`, `title`, `start_index`, `end_index` — which lets a client build a bibliography and highlight "data-backed claims" but proves nothing about support, because verifying requires re-fetching the page ([OpenAI web search guide](https://developers.openai.com/api/docs/guides/tools-web-search)). Vertex's older `groundingSupports` did the same over retrieved chunks. OpenAI is the only vendor that exposes the consulted-versus-cited distinction explicitly, returning a `sources` list that "often exceeds the number of inline citations shown" ([same](https://developers.openai.com/api/docs/guides/tools-web-search)).

**Mechanism two: carry the supporting passage back with the answer.** Anthropic's Citations API attaches citation objects to each output text block with a `cited_text` field, and the documentation makes a narrow but real guarantee: because the API parses citations and extracts `cited_text` directly, "citations are guaranteed to contain valid pointers to the provided documents" ([Citations](https://platform.claude.com/docs/en/build-with-claude/citations)). Citation granularity is a retrieval decision, not a model decision — "The text block is the minimal citable unit" ([Search results](https://platform.claude.com/docs/en/build-with-claude/search-results)) — and for web search, citations are always on, with `cited_text` capped at 150 characters and billed as neither input nor output tokens ([Web search tool](https://platform.claude.com/docs/en/agents-and-tools/tool-use/web-search-tool)). Consensus is the product analogue: it surfaces "the exact quote behind every citation" with click-through to the passage in the paper, calling it "a verification layer" ([Citation Grounding](https://consensus.app/home/workshops/citation-grounding/)). Elicit takes the strongest version of this position by not generating at all — information "is extracted directly from papers," with the source highlighted in the paper ([Elicit's reliability](https://support.elicit.com/en/articles/552897)). The important distinction: Anthropic's guarantee makes the *pointer* unfalsifiable while leaving the *prose* fallible. That is not "no hallucination," and should never be described as such.

**Mechanism three: constrain the corpus with allow/deny lists.** This is near-universal and is the only quality lever available at the API layer. OpenAI allows up to 100 allowed and 100 blocked domains with subdomains automatically included; Perplexity caps at 20 domains or URLs with path filtering and allow-or-deny but not both; Anthropic documents no count limit but has a `request_too_large` failure mode "typically because of a long domain filter list" ([OpenAI](https://developers.openai.com/api/docs/guides/tools-web-search); [Perplexity search filters](https://docs.perplexity.ai/guides/academic-filter-guide); [Anthropic web search](https://platform.claude.com/docs/en/agents-and-tools/tool-use/web-search-tool)). Only Perplexity ships true publication-date filters, and it is the only product distinguishing publication date from last-updated date — four date parameters plus a coarse `search_recency_filter`, and a `search_mode` corpus switch accepting `web`, `academic` and `sec` ([Perplexity](https://docs.perplexity.ai/guides/academic-filter-guide)). Anthropic's newest version turns source filtering into generated code: on `web_search_20260209` and later, "Claude can write and run code that filters the search results before they reach the context window" ([Anthropic web search](https://platform.claude.com/docs/en/agents-and-tools/tool-use/web-search-tool)) — expressive, but model-authored and therefore not auditable as a fixed policy.

In open source the picture is thinner. STORM is the only project with a real deny-list: 206 entries transcribed from Wikipedia's Perennial Sources page into three frozen sets ([retriever.py](https://github.com/stanford-oval/storm/blob/main/knowledge_storm/storm_wiki/modules/retriever.py)). It is also a cautionary tale, because the matcher tests `if domain in parsed_url.netloc` while the entries are Wikipedia *article titles* — `"Daily_Mail"` can never substring-match `dailymail.co.uk`, so only the handful written as real hostnames can ever fire. The right idea, keyed wrong, leaving roughly 95% of the list inert. gpt-researcher's equivalent is worse: `filter_urls` reads a `config.excluded_domains` key that exists in neither the config schema nor the defaults, and the function is never called from the pipeline ([web_scraping.py](https://github.com/assafelovic/gpt-researcher/blob/master/gpt_researcher/actions/web_scraping.py)).

**Mechanism four: score the source, not the claim.** Consensus is the only product documenting reputation signals, factoring "recency, citation count, and journal impact" into ranking over a corpus of 220M+ peer-reviewed papers ([Citation Grounding](https://consensus.app/home/workshops/citation-grounding/)). Local Deep Research is the only open-source project with a data-backed credibility database: `derive_quality_score` produces a 1–10 venue score from SJR quartile, h-index, and DOAJ membership, built from OpenAlex, DOAJ and predatory-journal lists, with predatory venues short-circuiting to an auto-remove threshold and a shipped exclusion threshold of 2 ([scoring.py](https://github.com/LearningCircuit/local-deep-research/blob/main/src/local_deep_research/journal_quality/scoring.py); [default_settings.json](https://github.com/LearningCircuit/local-deep-research/blob/main/src/local_deep_research/defaults/default_settings.json)). Its own docstring names the flaw — h-index carries "field-dependent bias" and field normalization "is not yet implemented" — which is a better epistemic standard than most vendors manage. gpt-researcher's `SourceCurator` is the counter-example: a single LLM call whose prompt says "Err on the side of inclusion" and "retain others unless clearly untrustworthy," which defaults to `CURATE_SOURCES: False`, and whose `json.loads` failure path silently returns the uncurated list after the UI has already announced that sources are being evaluated for credibility ([curator.py](https://github.com/assafelovic/gpt-researcher/blob/master/gpt_researcher/skills/curator.py); [prompts.py](https://github.com/assafelovic/gpt-researcher/blob/master/gpt_researcher/prompts.py)).

**What is absent everywhere.** No numeric per-claim support score is available from any current model API. Google shipped the only one, `confidenceScores` in `groundingSupports`, and retired it: "For Gemini 2.5 and after, this list will be empty and should be ignored" ([GroundingMetadata reference](https://cloud.google.com/vertex-ai/generative-ai/docs/reference/rest/v1beta1/GroundingMetadata)). No vendor documents what happens to a drafted claim that fails grounding. Cross-source corroboration exists only as prompt text — LangChain's "if three sources all say 'X', you could say 'These three sources all stated X'" ([prompts.py](https://github.com/langchain-ai/open_deep_research/blob/main/src/open_deep_research/prompts.py)) — with no code anywhere counting agreeing sources. And the sharpest articulation of the architectural problem comes from an unmerged contributor PR, not a maintainer: gpt-researcher #2090 argues that because `SourceCurator` runs *after* all scraped content has entered the research context, "Curating them afterward cannot undo that influence," and that "post-hoc curation isn't a quality trade-off — it invalidates the verification itself" because a fact-check is only meaningful when the evidence is independent of the claim's origin ([gpt-researcher#2090](https://github.com/assafelovic/gpt-researcher/pull/2090)).

## rootlogic already holds the position nobody else in the survey occupies

Four of rootlogic's existing guardrails are ahead of the surveyed field, and it is worth being precise about which.

**Per-claim verification against fetched page text.** `verify_findings` in `rootlogic/verify.py` takes each claim, assembles the text of up to three cited pages (fetched during research or re-fetched for the check), and has the model judge support against that text alone, with `prompts.VERIFIER` instructing it to "Judge ONLY from the evidence shown." The open-source survey found no project doing this. Local Deep Research comes closest in spirit with a verbatim-extraction prompt ("Output ONLY verbatim quotes from the page … never paraphrase facts"), but the thing it actually calls fact-checking is one unconstrained LLM call whose output is pasted as free text into the next prompt, ships with `general.enable_fact_checking = False`, and drives no programmatic decision ([standard_citation_handler.py](https://github.com/LearningCircuit/local-deep-research/blob/main/src/local_deep_research/citation_handlers/standard_citation_handler.py)).

**A code-level quote check, which is the part the literature says matters most.** `quote_in` squashes whitespace and quote characters, enforces `MIN_QUOTE = 12` characters, and confirms the quote really is a substring of the evidence; a `supported` verdict whose quote cannot be found is downgraded to `partially_supported` with the reason recorded in the note. This is exactly the structural benefit the attribution literature identifies: an exact-string quote is mechanically checkable with no model, no cost and no error rate, which converts a fuzzy verification problem into a deterministic one and leaves only the strictly smaller question of whether the quote supports the claim. The survey's grep found no such assertion in any of the four citing projects.

**Failure-to-read is never treated as evidence against a claim.** `verify.py` marks a claim `unverifiable` when no cited page yields at least `MIN_EVIDENCE = 200` characters, and maps the verifier's `no_usable_evidence` verdict to `unverifiable` rather than `unsupported`, with the comment that failing to read a page "tells us nothing about the claim." This is the abstention path GopherCite's numbers argue is the largest single marginal gain — human-rated high-quality-and-supported rose from 80%/67% to 90%/80% on NaturalQuestions/ELI5 once the model was allowed to decline ([arXiv:2203.11147](https://arxiv.org/abs/2203.11147)). Compare Local Deep Research's shipped `ForcedAnswerCitationHandler`, which instructs "NEVER say 'I cannot determine' or 'insufficient information'" and closes with "A wrong answer is better than no answer for this task" ([forced_answer_citation_handler.py](https://github.com/LearningCircuit/local-deep-research/blob/main/src/local_deep_research/citation_handlers/forced_answer_citation_handler.py)) — benchmark pressure operating directly against verification, in the same codebase as the best credibility database in the survey.

**Corroboration is computed in code, not prompted.** `corroborate` groups cited sources by registrable domain, excludes low-credibility sites from the independence count, and labels each claim `corroborated` (2+ independent domains), `single_source`, or `weak` (only low-credibility sources). No surveyed project computes an agreement count at all. rootlogic also filters at the boundary rather than after ingestion — `filters.filter_sources` drops blocked, non-allowlisted, duplicate, low-relevance and outdated sources with a logged reason before anything reaches analysis — which is precisely the architecture gpt-researcher#2090 is arguing for and failing to get merged.

**And one honest downgrade.** rootlogic's `check_report` citation-bounds repair, which rewrites any `[n]` outside `1..len(sources)` as `[?]`, is the same mechanism as STORM's `clean_up_citation` and carries the same limitation: it proves `n` exists, never that source `n` supports the sentence. STORM needed five separate merged PRs (#421, #428, #442, #443, #494) to get roughly forty lines of that logic correct — a useful data point on how easily even the trivial verification layer breaks.

## The measured results point at four specific, cheap upgrades

The single strongest cost/quality result in the area is MiniCheck: a ~770M-parameter Flan-T5 model reaching **74.7% balanced accuracy on LLM-AggreFact versus GPT-4's 75.3% and Claude-3 Opus's 74.1%**, at **$0.24 against $107** for the same 13K-example test set — roughly **400× cheaper at parity** ([arXiv:2404.10774](https://arxiv.org/abs/2404.10774)). For claim-versus-passage verification specifically, an LLM judge buys almost nothing. Two caveats travel with it: balanced accuracy tops out near 75% even for GPT-4, so per-claim verification is about a one-in-four-wrong process and should flag and rank rather than auto-reject; and LLM-AggreFact assumes the grounding document is supplied, making those numbers an upper bound for agents where retrieval itself can fail. rootlogic is unusually well placed here because it *does* supply the grounding document — `relevant_excerpt` hands the verifier the chunks of the page sharing the most words with the claim.

ALCE supplies the metric definitions that make citation quality computable, adjudicated by an NLI model rather than an LLM judge: **citation recall** is the fraction of sentences entailed by the *concatenation* of their cited passages, and **citation precision** is the fraction of individual citations that do work, where a citation scores zero if it alone cannot support the statement and removing it does not break entailment ([Gao et al., EMNLP 2023](https://aclanthology.org/2023.emnlp-main.398/)). Two consequences matter for rootlogic. First, recall alone is gameable: because all cited passages are concatenated before testing, a system can score perfectly while individual citations are junk — which is exactly what rootlogic's `_judge` does today when it hands the verifier up to three pages per claim and `quote_in` accepts a hit in any of them. Second, even the best models in ALCE "lack complete citation support 50% of the time" on ELI5, so a low score is a normal starting point rather than evidence of a broken pipeline.

VeriScore identifies the design decision that matters most for scoring a *report* rather than a QA answer: FActScore and SAFE both "assume that every claim is verifiable (i.e., can plausibly be proven true or false)," which real long-form output is not, so VeriScore extracts only the verifiable claims from each sentence before adjudicating ([arXiv:2406.19276](https://arxiv.org/abs/2406.19276)). Applying a FActScore-style ratio to a research report full of hedged synthesis produces noise on exactly those sentences. The cost of the full pipeline is the reason to copy the idea rather than the implementation: VeriScore "can take upwards of 100 seconds to evaluate a single response," which is what VeriFastScore was built to fix ([arXiv:2505.16973](https://arxiv.org/abs/2505.16973)). AttrScore adds a complementary refinement — three labels, **attributable / extrapolatory / contradictory** — because "extrapolatory" (the source is topically right but silent) and "contradictory" (the source says the opposite) demand different remediation; it also documents the failure modes that generalise to every NLI verifier, namely **disregard for numerical values** and inability to perform the symbolic operations a claim implies ([arXiv:2305.06311](https://arxiv.org/html/2305.06311v2)).

Finally, the academic-integrity signals are free, openly licensed, and deterministic — the only category in this entire survey where that is true. Crossref acquired the Retraction Watch database in September 2023 and publishes it as a **20-field CSV under CC BY 4.0, updated once per working day, no subscription**, pullable from `gitlab.com/crossref/retraction-watch-data` or queryable per-DOI through the REST API ([Crossref Retraction Watch docs](https://www.crossref.org/documentation/retrieve-metadata/retraction-watch/)). **Unpaywall needs no API key** — just an email — allows 100,000 calls/day, and returns OA status, best OA location, licence and version across 120M+ DOIs, where `submittedVersion` approximates "preprint" ([Unpaywall API](https://unpaywall.org/products/api)). **DOAJ's API is free at 2 requests/second**, with article metadata CC0 and journal metadata CC BY-SA 4.0 ([DOAJ API docs](https://doaj.org/docs/api/)). OpenAlex changed in 2026: API keys are now mandatory and usage is metered, but **singleton lookup by DOI costs $0** while search costs $0.001/call, against a $1/day free budget per key, and the full CC0 snapshot remains free ([OpenAlex pricing announcement](https://blog.openalex.org/openalex-api-new-features-and-usage-based-pricing/)) — so a design that resolves identifiers first and searches only as a fallback is now cheaper by construction.

## A prioritised set of adjustments for rootlogic

| # | Change | File | Evidence | Cost / risk |
|---|---|---|---|---|
| 1 | Require numeric claims' quotes to contain the number | `rootlogic/verify.py` | AttrScore: verifiers disregard numeric values | ~10 lines, no new calls; may over-downgrade reworded figures |
| 2 | Split `unverifiable` into unreadable-page vs not-a-checkable-claim | `verify.py`, `models.py`, `prompts.py` | VeriScore: not every claim is verifiable | one enum value + prompt line; model could abuse the new label |
| 3 | Attribute each quote to one cited URL; report citation precision | `verify.py`, `models.py` | ALCE: concatenated recall hides junk citations | ~30 lines, free; weaker than true leave-one-out |
| 4 | Annotate retractions, OA status and DOAJ inclusion | `filters.py` (+ cached CSV) | Retraction Watch CC BY 4.0, daily, free; Unpaywall keyless | one daily pull; DOI extraction from URLs is lossy |
| 5 | Collapse near-duplicate page bodies before counting corroboration | `verify.py` (`corroborate`) | Syndication keeps bodies, localises headlines | ~25 lines over text already in memory; no measured effect on agents |
| 6 | Optional MiniCheck adjudicator to lift coverage past 12 claims | new module behind an extra | 74.7% vs GPT-4 75.3%, ~400× cheaper | adds a model dependency; ~1-in-4 error rate |
| 7 | Replace the hand-rolled eTLD+1 heuristic with a PSL library | `verify.py` (`registrable_domain`) | PSL is the standard primitive for independence | small; bundled lists go stale |
| 8 | `--judge-model` for the hoax judge, plus a labelled meta-eval | `evaluate.py`, `evals/cases.json` | Self-enhancement bias; low-perplexity preference | few lines; meta-eval needs hand labels |

**Priority 1 — make numbers prove themselves.** rootlogic's entire verification guarantee rests on a string containment check, and the documented weak spot of every verifier in this family is numeric. AttrScore names "disregard for numerical values" and failure at "symbolic operations" as core failure modes of automatic attribution evaluators, and MiniCheck inherits them ([arXiv:2305.06311](https://arxiv.org/html/2305.06311v2)). `verify.py` already has the detector it needs: `_FACTUAL`, the regex used for report-level uncited-statement checks. Reuse it in `_judge` — if a claim contains a digit, a percentage, or a magnitude word, require that the accepted quote contain the matching numeric token before letting the verdict stand as `supported`, and downgrade to `partially_supported` with an explicit note otherwise. Cost is about ten lines and zero additional LLM calls. The risk is over-strictness: a page writing "8,848.86 metres" against a claim of "8848.86 m" must normalise (rootlogic's eval harness already does exactly this comma-stripping in `_mentions`), and a legitimately rounded figure will get downgraded. That is the correct direction of error for a research tool, and the downgrade is visible rather than silent.

**Priority 2 — stop conflating two different kinds of "unverifiable".** Right now `verify.py` assigns `unverifiable` in two structurally different situations: no cited page yielded `MIN_EVIDENCE` characters, and the verifier returned `no_usable_evidence` because the retrieved text was navigation, a paywall or the wrong page. Both are retrieval failures. VeriScore's contribution is the third case neither covers — the claim is not a verifiable proposition at all, which is common in a synthesis report full of hedged framing ([arXiv:2406.19276](https://arxiv.org/abs/2406.19276)). Add a distinct `not_verifiable_claim` verdict to `ClaimVerdictDraft` with a matching line in `prompts.VERIFIER`, keep the two retrieval-failure cases as `unverifiable`, and exclude the new category from `supported_ratio`'s denominator in `models.ReportQuality` the way `unverifiable` already is. This makes rootlogic's headline number mean "of the claims that could in principle be checked, this share held up" instead of silently mixing in propositions that were never checkable. Cost is an enum value, a prompt line and a report label. The risk is real and should be measured: a model handed an escape hatch will use it, so count the category per run and treat a rising share as a regression in the eval harness rather than a neutral fact.

**Priority 3 — make citation precision measurable, not just citation recall.** `_judge` currently hands the verifier all pages for a claim at once and `quote_in(v.quote, list(pages.values()))` accepts a hit in any of them. That is ALCE citation recall with concatenation, which the paper shows is gameable on its own: a claim can score `supported` while two of its three cited URLs contribute nothing ([Gao et al.](https://aclanthology.org/2023.emnlp-main.398/)). The cheap fix is to change `quote_in` to return *which* text matched, store that URL on `CheckedClaim` as the load-bearing source, and record the remaining cited URLs as unattributed. A run-level ratio of load-bearing citations to total citations is then a free metric, comparable across runs, and a per-claim signal the writer and the "Confidence and limitations" section can use. Cost is roughly thirty lines and no extra model calls. Be honest about the limitation: quote attribution is a proxy, not ALCE precision. A citation can genuinely support a claim without being the page the chosen quote came from, and true leave-one-out precision needs N additional adjudications per claim — which is affordable only once a cheap adjudicator exists (priority 6), not at Opus prices.

**Priority 4 — add the free academic signals, as annotations rather than filters.** This is the one external data category that is free, openly licensed, deterministic and uncontested. Extract a DOI or arXiv ID from a source URL, then check it against a locally cached Retraction Watch CSV (CC BY 4.0, one daily `git pull`, 20 fields including `RetractionDate` and `Reason`, no rate limit) and optionally Unpaywall for OA status and version ([Crossref](https://www.crossref.org/documentation/retrieve-metadata/retraction-watch/); [Unpaywall](https://unpaywall.org/products/api)). Local Deep Research's `derive_quality_score` is the template for turning this into a score, and its shipped `threshold = 2` plus per-engine enable flags is a clean settings pattern ([scoring.py](https://github.com/LearningCircuit/local-deep-research/blob/main/src/local_deep_research/journal_quality/scoring.py)). But rootlogic should deliberately not copy the auto-remove behaviour, and its own eval set proves why: the `mmr-autism` case in `evals/cases.json` requires the report to mention "retract". Blocking retracted papers outright would make the agent unable to explain that the Wakefield paper was retracted — the single most important fact about it. The right design is to set `Credibility(level="low", reason="retracted <date>: <reason>")` in `filters.py`, which lets rootlogic's existing machinery do the rest: a retracted paper can still support a claim, but `corroborate` will never let it do so alone, and `check_report` will list any takeaway resting only on it. Treat DOAJ inclusion as positive evidence rather than enumerating bad journals; the notes are explicit that predatory-journal screening has no free structured source, and Cabells itself argues that stale Beall's List mirrors "still hurt publishers" nearly a decade on ([Cabells](https://blog.cabells.com/2026/04/22/accusations-frozen-in-time-how-bealls-list-still-hurts-publishers-in-2026/)). Cost is one cached file plus a DOI regex; the risk is that DOI extraction from arbitrary URLs is lossy, so a miss must mean "no signal," never "clean".

**Priority 5 — deduplicate by origin before counting corroboration.** `corroborate` counts distinct registrable domains among credible cited sources, and `filter_sources` dedupes on normalised URL. Neither catches the case the truth-discovery literature warns about: three outlets carrying one wire story look like three independent confirmations. The syndication literature gives the concrete rule — syndicated stories keep the body while "locally replacing headlines and captions," which is why title matching fails and body near-duplicate detection works ([Alonso, Microsoft Research](https://www.microsoft.com/en-us/research/wp-content/uploads/2013/05/paper-1.pdf)). rootlogic is already holding the page bodies it needs: `verify_findings` mutates an `evidence` dict keyed by normalised URL. Shingle-hash those bodies, collapse near-duplicates into one independence unit, and surface the result in `claim_label` as, say, "2 independent sites (1 near-duplicate)". Cost is about twenty-five lines over data already in memory. The honesty requirement here is heavy, and it is why this sits at priority 5 rather than higher: **no paper measures the effect of source-independence weighting on an LLM research agent's factuality** — the truth-discovery and LLM-attribution literatures have simply not been connected — and the classic shared-error heuristic has a named failure mode, becoming "ineffective when sources copy information from a good source" ([Truth Discovery survey](https://arxiv.org/pdf/1505.02463)). So ship it as a visible label and a metric, not as a silent downgrade of the corroboration verdict.

**Priority 6 — an optional cheap adjudicator, to verify every claim instead of twelve.** rootlogic checks `max_claims = 12` claims per run by default, one `llm.structured` call per finding at `effort="medium"`. MiniCheck's numbers say the adjudication step specifically does not need a frontier model: 74.7% balanced accuracy against GPT-4's 75.3%, at $0.24 versus $107 on the same test set ([arXiv:2404.10774](https://arxiv.org/abs/2404.10774)). Because rootlogic already supplies the grounding passage through `relevant_excerpt`, the benchmark conditions transfer better here than for agents that verify against live search. The recommended shape is an optional extra (`pip install -e '.[verify]'`) exposing a second adjudicator behind the existing interface, used to screen *all* claims, with the Opus verifier reserved for decomposition-adjacent work and for claims where the cheap checker and the `quote_in` result disagree — inverting the instinct to use the LLM for everything. That also unlocks true ALCE leave-one-out precision, which is unaffordable at Opus prices. The costs are real and argue for keeping it optional: a torch-class dependency and a model download cut against rootlogic's "209 tests, no network" property, and at roughly one-in-four per-claim error the output must be used to rank and flag, never to auto-reject. Note also that no source measured claim-verification accuracy against *live* retrieval rather than a supplied document, so treat those figures as a ceiling.

**Priority 7 — use the Public Suffix List for the independence primitive.** `registrable_domain` in `verify.py` hand-rolls eTLD+1 with a fourteen-entry `_MULTI_PART_SUFFIXES` set. Every corroboration verdict depends on it, and the standard primitive is the PSL, with mature libraries in every major language including Python's `tldextract` ([Public Suffix List](https://en.wikipedia.org/wiki/Public_Suffix_List)). STORM's inert deny-list is the cautionary example of what mis-keyed domain matching costs. The offsetting risk is a supply-chain freshness one the notes flag directly: libraries compile a *copy* of the list, so a long-lived tool needs a refresh policy or it will mis-group newly delegated suffixes — and `tldextract` fetches remotely by default, which must be pinned to the bundled snapshot to preserve the no-network test guarantee. Given the current heuristic handles the common cases and the dependency brings a staleness obligation, this is a genuine improvement but not an urgent one.

**Priority 8 — grade the grader.** The hoax judge in `evaluate.py` is the same model that wrote the report unless configured otherwise, and the module docstring already says to treat hoax scores as indicative. The mechanism behind self-preference is now better understood than "models like themselves": judges "assign significantly higher evaluations to outputs with lower perplexity than human evaluators, regardless of whether the outputs were self-generated" ([arXiv:2410.21819](https://arxiv.org/abs/2410.21819)), which is a concrete reason a different model family decorrelates generator and judge. Add `--judge-model`, and add the labelled meta-eval the earlier research already identified — fifteen to twenty hand-labelled (report, statement, expected `asserted`) triples and a `metascore` — turning a caveat into a number. Worth noting for scope: the bias taxonomy that dominates LLM-as-judge discussion is largely a *pairwise-preference* phenomenon. Position bias needs two candidates to exist, so it does not apply to rootlogic's claim verification, which is single-item classification. The residual risk there is verbosity and fluency preference marking a well-written unsupported claim as supported — precisely the failure mode a research agent produces, and another argument for the specialised checker in priority 6.

## What is not worth adopting, and why

**Commercial credibility raters.** NewsGuard's methodology is genuinely rigorous — nine weighted pass/fail criteria totalling 100, human analysts, publisher right of reply, editorial review ([NewsGuard rating process](https://www.newsguardtech.com/ratings/rating-process-criteria/)) — but there is no public pricing, no public endpoint documentation, no public field schema, and the organisation is politically contested: a 2024 House Oversight investigation into alleged anti-conservative bias, a suit by The Daily Wire, The Federalist and the Texas AG over a State Department grant, and a Department of Defense contract ([Wikipedia: NewsGuard](https://en.wikipedia.org/wiki/NewsGuard)). Media Bias/Fact Check is paid, its API licence explicitly bars "large-scale commercial use, resale, redistribution, enterprise integration … or client-facing commercial products" ([MBFC API ratings](https://mediabiasfactcheck.com/mbfcs-api-ratings/)), and a July 2026 paper argues it "does not meet basic standards of rigor for academic research" and that its ratings substantially reflect one individual's opinions ([arXiv:2607.12108](https://arxiv.org/abs/2607.12108)) — MBFC's own disclaimer calls itself "not a tested scientific method." The Iffy Index is the only general-web list that is freely redistributable (content CC BY 4.0), but it is *derived from MBFC*, so combining the two is using one source twice while appearing to use two ([Iffy Index](https://iffy.news/index/)). rootlogic's existing answer is better than all of this: `sources block/allow/trust/distrust` puts a named, user-owned, user-visible rule in `filters.py` where `policy.adjust` overrides the model's credibility rating, with no hidden third-party arbiter and no political liability. If any external list is ever surfaced, it should be an attributed annotation ("NewsGuard: 62/100"), never a silent filter.

**Wikipedia's Perennial Sources list as a shipped blocklist.** The page itself says it is "not a policy, not a pre-approved source list, and not comprehensive," that "context matters tremendously," and that "absence of evidence is not evidence of absence"; it offers no API or structured export ([WP:RSP](https://en.wikipedia.org/wiki/Wikipedia:Reliable_sources/Perennial_sources)). STORM shipped it anyway and got a list that mostly cannot fire. The most a tool should do is surface it as context to the user, not enforce it.

**Retired vendor confidence scores.** Do not build a design that expects a numeric per-span grounding score from a model API. Google shipped the only one and turned it off for Gemini 2.5+, without publishing a reason, while moving to `url_citation` annotations — a deliberate shift from "score the grounding" to "expose the span and let the client verify" ([GroundingMetadata reference](https://cloud.google.com/vertex-ai/generative-ai/docs/reference/rest/v1beta1/GroundingMetadata)). rootlogic's verdict-plus-quote-plus-code-check is the correct shape for a world where no vendor supplies a score.

**The pre-LLM corroboration machinery.** The truth-discovery literature is mature and genuinely relevant — Bayesian copy detection, and Dong et al.'s HMMs over update histories that use *timing* as a dependence signal and therefore survive the copy-a-correct-source case ([VLDB 2009](http://www.vldb.org/pvldb/vol2/vldb09-335.pdf)) — but all of it predates LLMs, none of it has been evaluated on an LLM research agent, and the sophisticated versions require update histories rootlogic does not collect. Take the cheap proxies (body near-duplicate collapse, clustered publication timestamps) and leave the models. The literature also has nothing to say about the current contamination problem: many retrieved pages are now LLM summaries of each other.

**Vendor-blog effect sizes, and specific hallucination rates.** Claims that "citation-required prompting reduces unsupported claims by 50–80%" or that "citation enforcement reduces fabricated details to under 3%" come from vendor blogs with no published methodology, dataset or baseline, and must not be used to justify a design. Nor should rootlogic quote a hallucination rate for OpenAI deep research: the researchers could not retrieve the figure from a first-party page and explicitly flagged it as not-to-be-reported without re-verification.

**GPT Researcher's curation pattern, and post-hoc curation generally.** An LLM pass that runs after scraping, is prompted to err on the side of inclusion, defaults to off, and degrades silently on a parse error is worse than no curation, because the UI claims it happened. rootlogic's filter-at-the-boundary design is the one gpt-researcher#2090 is arguing for.

**C2PA content provenance.** Mature, free, cryptographically verifiable, with a CC-BY spec and free SDKs — and almost irrelevant to a text research assistant. Its semantics are asymmetric in a way that limits usefulness: a valid-and-trusted manifest is strong positive evidence, but *no manifest is near-zero evidence*, because stripping is the normal case for anything sourced from the web ([C2PA Specification 2.4](https://spec.c2pa.org/specifications/specifications/2.4/specs/C2PA_Specification.html)). Trust state is also time-varying — the Nikon Z6 III had C2PA suspended and all certificates revoked after a signing vulnerability — so any cached verdict needs a timestamp and re-checking.

## Caveats the researchers flagged, and that this report inherits

The most important framing point in the whole survey comes from GopherCite's own authors: **"not all claims supported by evidence are true."** Every metric discussed here — ALCE precision and recall, MiniCheck balanced accuracy, RAGAS and DeepEval faithfulness, and rootlogic's own `supported_ratio` — measures **attribution, not truth**. A model quoting a wrong source verbatim is perfectly attributable and perfectly false ([arXiv:2203.11147](https://arxiv.org/abs/2203.11147)). rootlogic's own `verify.py` docstring already says this ("Verification can't prove a claim true, only that its cited source says it"), and every improvement above makes the attribution number better, not the truth number. Only FActScore/SAFE/VeriScore-style pipelines against a trusted corpus approach truth, and only as far as the corpus is right.

Several findings rest on sources that could not be fetched directly and are reported second-hand from search summaries: Google's Vertex `GroundingMetadata` reference (including the `confidenceScores` retirement text), Consensus's help pages, Elicit's reported 96% extraction accuracy and 1.0% hallucination rate against human reviewers, and Perplexity's own factuality figures. The Vertex `dynamicThreshold` default could not be verified at all, and the MBFC data-API page returned HTTP 403, so its tiers and rated-source counts are unconfirmed. Exact numbers for ALCE's human-agreement correlation, SAFE's F1@K formula, VeriScore's agreement percentage and VeriFastScore's speedup all sit in paper bodies that were not extracted, and one extraction of ALCE's dataset list conflicts with the canonical ASQA/QAMPARI/ELI5 triple. The open-source claim that no project verifies claims against page text is bounded by the five named projects surveyed, not the whole ecosystem. And SAFE's "superhuman" framing is contested: its 72% agreement baseline was crowdsourced annotators, not the qualified freelance fact-checkers FActScore used, which largely explains the gap to FActScore's 88–96% inter-annotator agreement — so nobody should expect 90%+ agreement on open-web verification of arbitrary report claims.

## Conclusion

The gap between rootlogic and the field is not a feature gap, it is a measurement gap. rootlogic already implements the mechanism the survey found missing everywhere — a claim checked against the text of its cited page, with code confirming the quote — and already gets the hard epistemic calls right, refusing to read an unfetchable page as evidence against a claim and never letting a low-credibility source corroborate alone. What it cannot currently say is *how well any of that works*: `supported_ratio` mixes verifiable and unverifiable claims into one denominator, accepts a quote found in any of three cited pages, and covers twelve claims per run. Every high-priority recommendation above is a measurement fix disguised as a feature — split the denominator, attribute the quote, force numbers to appear — and all three are dozens of lines of deterministic code with no new model calls. That ordering is not an accident. In a domain where the best available adjudicator is wrong about one claim in four, the durable advantage comes from the checks that have no error rate at all.

The second insight worth carrying forward is where the field's incentives actually point. Local Deep Research ships the best venue-credibility database in the survey *and* a citation handler that says "A wrong answer is better than no answer"; gpt-researcher's best verification argument sits in an unmerged PR with zero comments; gpt-researcher's hallucination-eval PR was closed unmerged and two successors have been open for a year; STORM's citation-evaluation script existed in 2024 and is gone at HEAD. Benchmarks reward answering, not abstaining, and citation problems get triaged as numbering bugs rather than truth bugs. rootlogic's eval set inverts that pressure by design — hoaxes it must not repeat, contested topics where it must surface disagreement, and a floor of 70% of checked claims holding up — which means the cheapest way to keep the advantage is to add the two metrics the harness currently lacks, citation precision and the share of claims that were never checkable, and then watch them across runs. A verification layer nobody measures decays into exactly the decorative feature the rest of the field has shipped.
