# External Standards and Data Sources for Judging Source Trustworthiness and Content Provenance

Scope note: research conducted September 2026. Where a fact could only be established from a secondary or SEO-farm source, that is flagged inline. Costs and licences are stated where a primary page gave them; otherwise listed as a gap.

## Content provenance: C2PA / Content Credentials, IPTC, and the limits

### Takeaway
C2PA is the only mature, cryptographically verifiable provenance standard, now at spec version 2.4 (April 2026), with a free CC-BY spec, free open-source SDKs (Rust, Python, JS, C++, iOS, Android) and a formal Conformance Program with trust lists — but it is opt-in, easily stripped by ordinary platform processing, and only attests what the signer chose to assert, so absence of a manifest tells an agent essentially nothing. IPTC's `digitalSourceType` vocabulary is the lightweight, widely-adopted complement for flagging AI-generated media, but it is unsigned metadata and trivially removable.

### Cited Findings

**C2PA specification**
- The current C2PA Technical Specification is **version 2.4, published April 2026**, licensed **CC-BY 4.0** — [C2PA Specification 2.4](https://spec.c2pa.org/specifications/specifications/2.4/specs/C2PA_Specification.html)
- Version history is contested across secondary sources: one set of 2026 write-ups describe **2.2 (2025-05-01)** as "the current stable release" and **2.3 as published February 2026**, while the spec site itself serves 2.4 — [C2PA Spec 2.2 PDF (2025-05-01)](https://spec.c2pa.org/specifications/specifications/2.2/specs/_attachments/C2PA_Specification.pdf); [spec.c2pa.org 2.4](https://spec.c2pa.org/specifications/specifications/2.4/specs/C2PA_Specification.html). Treat 2.4 as current and 2.2 as the version most deployed tooling targets.
- A **C2PA Manifest** contains four elements: a **Claim** (signed structure splitting `created_assertions` from `gathered_assertions`), **Assertions** (creation details, edits, device info, thumbnails, hashes), a **Claim Signature**, and **Content Bindings** — [C2PA Specification 2.4](https://spec.c2pa.org/specifications/specifications/2.4/specs/C2PA_Specification.html)
- **Hard bindings** use cryptographic hashes (byte-range, box-based, BMFF) tying the manifest to exact bytes; **soft bindings** use perceptual fingerprints or invisible watermarks so derived renditions can still be matched — [C2PA Specification 2.4](https://spec.c2pa.org/specifications/specifications/2.4/specs/C2PA_Specification.html)
- Manifests can also reference **ingredients** (component assets in a composed work), which is what makes an edit chain auditable — [C2PA Specification 2.4](https://spec.c2pa.org/specifications/specifications/2.4/specs/C2PA_Specification.html)
- Validation produces one of **three states: "well-formed", "valid", and "trusted"**; "trusted" additionally requires the signing certificate to chain to the **C2PA Trust List** (approved CAs) or the **C2PA TSA Trust List** (time-stamping authorities), and validators may configure custom trust lists — [C2PA Specification 2.4](https://spec.c2pa.org/specifications/specifications/2.4/specs/C2PA_Specification.html)
- **Durable Content Credentials** are defined in-spec as "a Content Credential for which there exists one or more soft bindings that enable its discovery in a manifest repository" — i.e. if the manifest is stripped, a fingerprint/watermark lookup can recover it from a repository — [C2PA Specification 2.4](https://spec.c2pa.org/specifications/specifications/2.4/specs/C2PA_Specification.html)
- **Critical limitation stated by the spec itself:** asset metadata *outside* the C2PA manifest is not attributed to the signer even when covered by a hard binding. EXIF GPS coordinates, for example, remain unattested unless explicitly copied into a `c2pa.metadata` assertion inside `created_assertions` — [C2PA Specification 2.4](https://spec.c2pa.org/specifications/specifications/2.4/specs/C2PA_Specification.html)

**Programmatic verification**
- Open-source verification stack: **c2patool** (CLI wrapper that prints a JSON manifest report), **c2pa-rs** (the Rust library described as "the fundamental system underlying everything else"), plus SDKs for **Python, C++, Node.js, JavaScript, iOS and Android**, all able to read, validate, create and sign manifest data — [Content Authenticity open-source docs](https://opensource.contentauthenticity.org/docs/introduction/)
- The **C2PA Conformance Program and official C2PA Trust List launched mid-2025**; the **Interim Trust List (ITL) was frozen as of 1 January 2026** — no new entries, no updates — so new implementations must go through formal conformance evaluation — [C2PA Conformance](https://c2pa.org/conformance/); [C2PA ITL frozen notice](https://c2pa.ai/news/itl-frozen); [trust-list PEM in c2pa-org/conformance-public](https://github.com/c2pa-org/conformance-public/blob/main/trust-list/C2PA-TSA-TRUST-LIST.pem)

**Adoption (2026)**
- Cameras signing at capture include **Leica (M11/M11-P, Q3, SL3)**, **Sony (Alpha 1 II, Alpha 9 III, Xperia 1 VI)**, **Nikon (Z8, Z9, Zf via firmware)** and **Canon (EOS R1, R5 Mark II)**; Leica M11-P was the first consumer camera with Content Credentials built in — [C2PA supported devices](https://c2paviewer.com/supported-devices); [AttestTrail C2PA camera list](https://attesttrail.com/blog/c2pa-cameras-support)
- **Nikon Z6 III** received C2PA by firmware in August 2025, then had it **suspended after a signing vulnerability, with all certificates revoked**, and the service was still not restored as of early 2026 — [AttestTrail](https://attesttrail.com/blog/c2pa-cameras-support). This is a useful worked example that a "trusted" manifest can later become untrusted via revocation.
- **Samsung Galaxy S25** shipped C2PA (first major smartphone line), with Google following in Pixel using Qualcomm Snapdragon secure-element infrastructure — [SoftwareSeni C2PA adoption 2026](https://www.softwareseni.com/c2pa-adoption-in-2026-hardware-platforms-and-verification-reality/)
- **TikTok has labelled over 1.3 billion AI-generated or AI-edited videos using C2PA**, described as the largest single deployment by volume as of mid-2026; **Meta** reads C2PA on upload and shows "AI Info" labels with server-side credential records; **X** added credential display in March 2026 for Premium users; **LinkedIn** preserves credential chains through upload — [Editors Weblog C2PA adoption tracker](https://editorsweblog.org/2026/04/12/c2pa-adoption-tracker-platforms-content-credentials-2026); [SoftwareSeni](https://www.softwareseni.com/c2pa-adoption-in-2026-hardware-platforms-and-verification-reality/). These platform figures come from trade/SEO-style secondary sources, not first-party platform statements; treat the 1.3 billion figure as unverified.

**IPTC**
- IPTC's **Digital Source Type NewsCodes vocabulary** (introduced 2023) is the canonical controlled vocabulary for declaring how media was produced; canonical URL `http://cv.iptc.org/newscodes/digitalsourcetype` — [IPTC Digital Source Type vocabulary](https://cv.iptc.org/newscodes/digitalsourcetype)
- IPTC recommends software generating images with trained AI models set Digital Source Type to **`trainedAlgorithmicMedia`** in the **XMP packet** of generated image and video files; the vocabulary also includes **`compositeWithTrainedAlgorithmicMedia`** (added for generative inpainting/outpainting) and **`digitalArt`** — [IPTC synthetic media guidance](https://iptc.org/news/iptc-publishes-metadata-guidance-for-ai-generated-synthetic-media/); [IPTC inpainting/outpainting term](https://iptc.org/news/new-digital-source-type-term-added-to-support-inpainting-outpainting-in-generative-ai/)
- **OpenAI, Adobe, Google and Microsoft** have committed to emitting these IPTC codes, so DALL·E, Firefly and Imagen outputs carry Digital Source Type metadata — [IPTC synthetic media guidance](https://iptc.org/news/iptc-publishes-metadata-guidance-for-ai-generated-synthetic-media/)
- General IPTC photo metadata field definitions live in the **IPTC Photo Metadata User Guide** — [IPTC Photo Metadata User Guide](https://www.iptc.org/std/photometadata/documentation/userguide/)

**Documented limits and attacks**
- C2PA "is metadata with a signature": screenshots, re-encoding, and social-platform processing cause it to stop being displayed, and platforms routinely strip metadata on upload — [truescreen: C2PA limits](https://truescreen.io/articles/c2pa-standard-history-limitations/)
- **Re-signing attacks**: an adversary can strip a manifest and reattach one with altered assertions — [truescreen](https://truescreen.io/articles/c2pa-standard-history-limitations/)
- Academic work describes **"metadata washing"** workflows that produce *authenticated fakes* through standard editing pipelines, requiring no cryptographic compromise — only the semantic omission of a single assertion field that the current C2PA spec permits — [Authenticated Contradictions from Desynchronized Provenance and Watermarking (arXiv 2603.02378)](https://arxiv.org/html/2603.02378v1)
- Watermark robustness (the mechanism behind durable credentials) is under active attack: diffusion-based denoise-and-reconstruct attacks remove watermarks with high precision — [Editing Away the Evidence (arXiv 2603.12949)](https://arxiv.org/pdf/2603.12949); [TrustMark (arXiv 2311.18297)](https://arxiv.org/pdf/2311.18297)
- The **World Privacy Forum** has published a technical review of privacy, identity and trust issues in the C2PA framework — [World Privacy Forum: Privacy, Identity and Trust in C2PA](https://worldprivacyforum.org/posts/privacy-identity-and-trust-in-c2pa/)

### Inferences
- For an engineer: C2PA verification is cheap to wire in (free spec, free SDKs, no API key, no per-call cost) and produces a three-valued result that maps neatly onto a confidence field. The correct semantics are **asymmetric**: a *valid + trusted* manifest is strong positive evidence; *no manifest* is near-zero evidence, because stripping is the normal case for web-sourced media.
- Because "trusted" depends on trust-list membership and revocation state, the verification result is **time-varying**. The Nikon Z6 III certificate revocation means a previously-trusted asset can become untrusted. A cache of verification verdicts should therefore carry a timestamp and be re-checked, not treated as immutable.
- Treat IPTC `digitalSourceType` as a **hint, not a signal**: it is unsigned, so its presence is weak positive evidence of AI generation (few adversaries add it voluntarily) while its absence proves nothing.
- The spec's own warning about unattested EXIF is a concrete implementation trap: a naive verifier that reads EXIF GPS/date from a C2PA-signed file and reports it as "verified" is wrong.

### Gaps
- The open-source docs page did not state the **licences of c2patool / c2pa-rs / the SDKs** (widely believed to be Apache-2.0/MIT dual, but not confirmed from a primary page here).
- No primary-source confirmation was found for the TikTok 1.3-billion-label figure or the X/Meta/LinkedIn behaviours; all come from secondary trade blogs.
- No authoritative count of C2PA-conformant generator products or CAs on the current Trust List was retrieved.

## Source credibility data available to programs

### Takeaway
There is no free, well-licensed, machine-readable general web-credibility database. The commercially maintained ones (NewsGuard, Ad Fontes, MBFC) are paid and/or restrictively licensed and all three are contested; the freely reusable ones (Iffy Index at CC BY 4.0, Wikipedia's Perennial Sources list) are narrow, derivative, or not machine-readable. Scholarly-source metadata (OpenAlex, Crossref, DOAJ, Unpaywall) is by contrast genuinely free and openly licensed.

### Cited Findings

**NewsGuard — commercial, licensed, no public pricing**
- Ratings are produced by **human "trained journalists"**: an analyst assesses the site against nine criteria, drafts a "Nutrition Label", the publisher is contacted for comment, and a senior editor plus a co-CEO review and fact-check before publication — [NewsGuard rating process and criteria](https://www.newsguardtech.com/ratings/rating-process-criteria/)
- The **nine pass/fail criteria and weights** (total 100): does not publish false/misleading content (22); gathers and presents information responsibly (18); effective practices for correcting errors (12.5); handles news/opinion distinction responsibly (12.5); avoids deceptive headlines (10); discloses ownership and financing (7.5); clearly labels advertising (7.5); reveals who is in charge and conflicts of interest (5); provides content creators' names and contact info (5) — [NewsGuard rating process and criteria](https://www.newsguardtech.com/ratings/rating-process-criteria/)
- **Score bands**: 100 = High Credibility; 75–99 Generally Credible; 60–74 Credible with Exceptions; 40–59 Proceed with Caution; 0–39 Proceed with Maximum Caution. Plus non-numeric **Satire** and **Platform** designations — [NewsGuard rating process and criteria](https://www.newsguardtech.com/ratings/rating-process-criteria/)
- Ratings are "accessible via web dashboard, API or cloud datastream", and each rated publisher gets a 0–100 reliability score, a rating level, and **more than 30 descriptive metadata fields** about ownership, content and operations — [NewsGuard News Reliability Ratings](https://www.newsguardtech.com/solutions/news-reliability-ratings/)
- **Business model is licensing fees** from access providers, platforms, search engines, AI providers and advertisers; NewsGuard reported profitability in January 2022. Consumer pricing was previously **$1.95/month**, free for Microsoft Edge users, libraries and schools — [Wikipedia: NewsGuard](https://en.wikipedia.org/wiki/NewsGuard)
- NewsGuard markets a specific AI-training product line ("NewsGuard for AI: Training Machines with Trust Data") — [NewsGuard press release](https://www.newsguardtech.com/press/launch-of-newsguard-for-ai-training-machines-with-trust-data/)
- NewsGuard also publishes an **AI Tracking Center**: **3,749 AI Content Farm news/information sites across 16 languages, last updated 23 June 2026** (up from 3,006 on 12 March 2026) — [NewsGuard AI Tracking Center](https://www.newsguardtech.com/special-reports/ai-tracking-center/). A real-time "AI Content Farm detection datastream" is sold separately — [NewsGuard press release](https://www.newsguardtech.com/press/newsguard-launches-real-time-ai-content-farm-detection-datastream-to-counter-onslaught-of-ai-slop-in-news/)

**NewsGuard — criticism (contested)**
- Joshua Benton (Columbia Journalism Review, 2018) argued the at-a-glance labelling conflicts with "the nuance modern media literacy requires" — [Wikipedia: NewsGuard](https://en.wikipedia.org/wiki/NewsGuard)
- US conservatives and Republican politicians, citing a **Media Research Center** study, alleged NewsGuard scores left-leaning outlets higher; in 2024 **House Oversight Committee chairman James Comer opened an investigation** alleging anti-conservative bias. NewsGuard's co-CEO **L. Gordon Crovitz** responded that The Daily Caller and Daily Wire outscore comparable liberal brands and Fox News outscores MSNBC — [Wikipedia: NewsGuard](https://en.wikipedia.org/wiki/NewsGuard)
- **The Daily Wire, The Federalist and Texas AG Ken Paxton sued the US State Department (2024)** over a **$25,000** Global Engagement Center grant to NewsGuard, arguing it funded technology that censored right-leaning outlets; Judge Jeremy Kernodle allowed the case to proceed — [Wikipedia: NewsGuard](https://en.wikipedia.org/wiki/NewsGuard)
- **FCC appointee Brendan Carr** publicly accused NewsGuard of censorship and pressured tech companies against partnerships (2024); legal commentators noted First Amendment concerns about that pressure — [Wikipedia: NewsGuard](https://en.wikipedia.org/wiki/NewsGuard)
- A **2025 defamation suit by the Consortium for Independent Journalism was dismissed** by a US District Court for insufficient evidence of actual malice — [Wikipedia: NewsGuard](https://en.wikipedia.org/wiki/NewsGuard)
- NewsGuard holds a contract with the **US Department of Defense** — [Wikipedia: NewsGuard](https://en.wikipedia.org/wiki/NewsGuard). This matters for an agent builder: relying on NewsGuard imports a politically contested, state-adjacent arbiter into the pipeline.

**Media Bias/Fact Check (MBFC) — paid API, restrictive licence, heavily criticised**
- MBFC publishes a formal **API Data License Agreement** (PDF). Key terms: the agreement runs until terminated; MBFC may terminate **if you exceed the monthly request limit** or breach other terms; on termination you must **cease all use of the API data** — [MBFC API License Agreement (PDF)](https://mediabiasfactcheck.com/wp-content/uploads/2024/05/MBFC-API-License.pdf)
- Limited API access is offered via **RapidAPI** for developers, educators, researchers, testing, PoC and small-volume apps; RapidAPI access is **explicitly not for large-scale commercial use, resale, redistribution, enterprise integration, high-volume access, or client-facing commercial products**. Public use should carry attribution and a hyperlink to mediabiasfactcheck.com — [MBFC's API Ratings](https://mediabiasfactcheck.com/mbfcs-api-ratings/); [MBFC on RapidAPI](https://rapidapi.com/mbfcnews/api/media-bias-fact-check-ratings-api2)
- **Academic critique (July 2026)**: Ruiz Iglesias, Witte Zimmerman, Fehr, Dodds and Danforth, *"Stop using Media Bias/Fact Check in research"* (submitted 13 July 2026, revised 21 July 2026) argue MBFC "does not meet basic standards of rigor for academic research"; that researchers routinely describe it in ways contradicting its own About page; that its ratings substantially reflect **one individual's opinions**; and that continued research use "erases the provenance" of the scores. They characterise the dataset as "a computationally legible account of hegemony" — [arXiv 2607.12108](https://arxiv.org/abs/2607.12108)
- MBFC's own disclaimer, quoted in that paper, is that it is **"not a tested scientific method… [but] a simple guide to the idea of a source's bias"** — [arXiv 2607.12108](https://arxiv.org/abs/2607.12108)
- MBFC's response is that it is a human-driven media-rating organisation, not a fact-checking organisation or peer-reviewed journal, and that ratings should be used with its published methodology, scope and limitations in mind — [MBFC About](https://mediabiasfactcheck.com/about/); [MBFC Methodology](https://mediabiasfactcheck.com/methodology/)

**Ad Fontes Media — human panel ratings, contested**
- Methodology: **multi-analyst ratings along seven categories of bias and eight of reliability**, by a team of **40+ analysts** who receive **30 hours of initial training plus ~40 hours of ongoing training per year** — [Ad Fontes methodology](https://adfontesmedia.com/methodology/); [Ad Fontes content analysis white paper](https://adfontesmedia.com/methodology-white-paper/)
- Analysts take an internal political bias test (self-ranking on ~20 policy positions) so each review panel can be staffed with **one centrist, one left-leaning and one right-leaning analyst** — [Ad Fontes methodology](https://adfontesmedia.com/methodology/)
- **Criticism**: a 2021 analysis by research librarians argued the panel-balance approach creates a **false equivalency between left and right**, and described the chart as "a meme, not an information literacy tool". Founder Vanessa Otero responded publicly, acknowledging limits but defending the method — [Poynter: Should you trust media bias charts?](https://www.poynter.org/fact-checking/media-literacy/2021/should-you-trust-media-bias-charts/); [Wikipedia: Ad Fontes Media](https://en.wikipedia.org/wiki/Ad_Fontes_Media)
- A comparable API exists from **AllSides** ("Bias Checker API") — [AllSides Bias Checker API](https://www.allsides.com/tools-services/bias-checker-api)

**Wikipedia Perennial Sources (RSP) — free content, not machine-readable**
- Five status categories: **Generally Reliable, No Consensus, Generally Unreliable, Deprecated, Blacklisted**. Entries require "an uninterrupted request for comment… or two or more significant discussions" at the reliable sources noticeboard — [WP:RSP](https://en.wikipedia.org/wiki/Wikipedia:Reliable_sources/Perennial_sources)
- The page explicitly states it is **not a policy, not a pre-approved source list, and not comprehensive**; that "context matters tremendously"; and that "absence of evidence is not evidence of absence" — [WP:RSP](https://en.wikipedia.org/wiki/Wikipedia:Reliable_sources/Perennial_sources)
- **No API or structured export is offered** by the page itself; it is a wikitable split across sub-pages (a separate page covers sources from "S" onward) — [WP:RSP](https://en.wikipedia.org/wiki/Wikipedia:Reliable_sources/Perennial_sources)
- Academic work treats the perennial sources list as "a collection of reliability labels for web domains identified and collaboratively agreed upon by Wikipedia editors"; as of May 2023 it existed in **12 language editions**, of which **only six (English, Russian, French, Persian, Swedish, Chinese) were actively maintained** — [A Comparative Study of Reference Reliability in Multiple Language Editions of Wikipedia (arXiv 2309.00196)](https://arxiv.org/pdf/2309.00196)
- Wikimedia Research runs a **Knowledge Integrity** programme covering source reliability work — [Wikimedia Research: Knowledge Integrity](https://research.wikimedia.org/knowledge-integrity.html)
- Wikipedia content is **CC BY-SA 4.0**; machine-readable parsed Wikipedia (English and French) with revision/editor/licence metadata is distributed by **Wikimedia Enterprise** on Hugging Face and Kaggle — [wikimedia/structured-wikipedia on Hugging Face](https://huggingface.co/datasets/wikimedia/structured-wikipedia); [Wikimedia Enterprise blog](https://enterprise.wikimedia.com/blog/hugging-face-dataset/)

**Iffy Index — the one cleanly reusable list**
- The Iffy Index compiles **unreliable news sources that regularly fail fact checks**, deliberately excluding sources that merely show political bias — [Iffy Index](https://iffy.news/index/)
- **It is derivative of MBFC**: inclusion is limited to sites MBFC rates "Low Credibility" and categorises as conspiracy/pseudoscience or questionable. Supplementary signals come from Wikipedia fake-news lists and domain quality scores (Similarweb rankings) — [Iffy Index](https://iffy.news/index/)
- Available as a **public Google Spreadsheet, JSON (via OpenSheet or direct download) and CSV**; **content is CC BY 4.0, code is MIT** — [Iffy Index](https://iffy.news/index/)

### Inferences
- For a research tool, the honest licensing picture is: **Iffy Index (CC BY 4.0) is the only general-web credibility list you can freely redistribute**, and it inherits every MBFC methodological objection plus a low-credibility-only scope. Everything else is either paid (NewsGuard, MBFC API, presumably Ad Fontes), licence-restricted against product embedding (MBFC via RapidAPI), or not machine-readable (WP:RSP).
- WP:RSP is best consumed as a **periodically re-scraped snapshot with a human-reviewed domain mapping**, and its own caveats argue for surfacing it to the user as context ("Wikipedia editors have deprecated this source") rather than using it as an automatic filter.
- Given the arXiv critique that MBFC scores trace to essentially one person's judgement, any system that uses MBFC *and* Iffy Index is using **one source twice**, not two independent signals. Same-provenance double-counting is a real risk when combining these lists.
- The defensible design is to treat all of these as **attributed, user-visible annotations with a named provenance** ("NewsGuard: 62/100") rather than as a hidden trust score, which also sidesteps the political liability the NewsGuard controversies illustrate.

### Gaps
- **NewsGuard API pricing, endpoint documentation, field schema and licence terms are not public.** The company describes API and datastream access but publishes no rate card or developer docs reachable without sales contact.
- **Ad Fontes Media licensing and API availability could not be established.** No pricing, terms, or developer documentation was found.
- The **MBFC data API page (mediabiasfactcheck.com/mbfcs-data-api/) returned HTTP 403** to automated fetching, so MBFC's own stated tiers, prices, rate limits and rated-source count are unconfirmed here; only the licence PDF and the RapidAPI description could be read.
- No total count of sources on WP:RSP or in the Iffy Index was obtainable (both render dynamically).

## Academic-source signals

### Takeaway
This is the strongest area by far: retraction status, open-access/peer-review status, journal inclusion and citation counts are all available from free, openly licensed first-party APIs (Crossref, OpenAlex, DOAJ, Unpaywall, Semantic Scholar). The one material 2026 change is that **OpenAlex now requires an API key and meters usage**, though the full CC0 snapshot remains free. Predatory-journal detection is the weak spot — the only structured successor to Beall's List is subscription-only.

### Cited Findings

**Retraction status — free, CC BY 4.0**
- Crossref **acquired the Retraction Watch database from the Center for Scientific Integrity in September 2023** and made it publicly available — [Crossref blog](https://www.crossref.org/blog/retraction-watch-retractions-now-in-the-crossref-api/); [LSE Impact Blog](https://blogs.lse.ac.uk/impactofsocialsciences/2023/09/27/making-retraction-data-freely-accessible-why-crossrefs-acquisition-of-the-retraction-watch-database-is-a-big-step-forward/)
- Two access paths: the **Crossref REST API** with `filter=update-type:retraction` (e.g. `https://api.crossref.org/v1/works?filter=update-type:retraction`), and a **full CSV dump from a Git repo at `https://gitlab.com/crossref/retraction-watch-data`** — [Crossref Retraction Watch docs](https://www.crossref.org/documentation/retrieve-metadata/retraction-watch/)
- For a single DOI, query `api.crossref.org/works/[DOI]` and inspect the **`update-to` / `relation`** fields for a retraction or correction notice — [Crossref community forum](https://community.crossref.org/t/retraction-watch-retractions-now-in-the-crossref-api-crossref/13119)
- The CSV carries **20 fields**: Record ID, Title, Subject, Institution, Journal, Publisher, Country, Author, URLs, ArticleType, RetractionDate, RetractionDOI, RetractionPubMedID, OriginalPaperDate, OriginalPaperDOI, OriginalPaperPubMedID, RetractionNature, Reason, Paywalled, Notes — [Crossref Retraction Watch docs](https://www.crossref.org/documentation/retrieve-metadata/retraction-watch/)
- **Licence: CC BY 4.0**; updated **once per working day**; **no subscription required**. Crossref metadata generally is free to reuse without a licence, but Crossref requests a citation if Retraction Watch retraction metadata is used in published work — [Crossref Retraction Watch docs](https://www.crossref.org/documentation/retrieve-metadata/retraction-watch/); [Crossref blog](https://www.crossref.org/blog/retraction-watch-retractions-now-in-the-crossref-api/)
- Retracted work continues to propagate: a September 2025 study documents **the persistence of retracted papers as Wikipedia citations** — [The Persistence of Retracted Papers on Wikipedia (arXiv 2509.18403)](https://arxiv.org/pdf/2509.18403)

**OpenAlex — free data, now metered API**
- OpenAlex is a **CC0-licensed** scholarly metadata catalogue maintained by the nonprofit **OurResearch**; the full **~480M-work dataset is free to download, share, remix and build on** from a public AWS S3 snapshot, with no account or key needed for bulk access, and is **unaffected by the API pricing model** — [OpenAlex blog: new features and usage-based pricing](https://blog.openalex.org/openalex-api-new-features-and-usage-based-pricing/)
- **API keys became mandatory** (announced January 2026, in effect around **13–24 February 2026** — sources differ on the exact date). Keys are **free** and take about 30 seconds to obtain — [OpenAlex blog](https://blog.openalex.org/openalex-api-new-features-and-usage-based-pricing/); [openalex-users Google Group: "API keys required starting Feb 13"](https://groups.google.com/g/openalex-users/c/rI1GIAySpVQ)
- **Usage-based pricing**: single work lookup by DOI/ID **$0**; list-and-filter **$0.0001/call ($0.10 per 1,000)**; search **$0.001/call ($1.00 per 1,000)**; PDF/XML download **$0.01/call ($10.00 per 1,000)** — [OpenAlex blog](https://blog.openalex.org/openalex-api-new-features-and-usage-based-pricing/)
- Each key gets **$1 of free usage per day**, which at 100 works per request equals **unlimited singleton lookups, 10,000 list/filter calls (1M results), 1,000 search calls (100K results), or 100 PDF/XML calls**. Without a key the budget is $0.01/day — [OpenAlex blog](https://blog.openalex.org/openalex-api-new-features-and-usage-based-pricing/); [CASRAI summary](https://casrai.org/news/openalex-api-keys-mandatory-usage-based-pricing-2026)
- **Member, Member+ and Supporter** premium plans offer annual pricing with higher budgets, data sync, curation dashboards, and special filters such as `from_updated_date` — [OpenAlex blog](https://blog.openalex.org/openalex-api-new-features-and-usage-based-pricing/); [OpenAlex pricing page](https://help.openalex.org/hc/en-us/articles/24397762024087-Pricing)
- API reference and rate-limit/authentication docs — [OpenAlex API reference](https://help.openalex.org/api/); [rate limits and authentication (source)](https://github.com/ourresearch/openalex-docs/blob/main/how-to-use-the-api/rate-limits-and-authentication.md)

**Semantic Scholar**
- The Academic Graph API provides "data about authors, papers, citations, venues, SPECTER2 embeddings", plus metadata such as PDF URLs, abstracts and summarisation — [Semantic Scholar API](https://www.semanticscholar.org/product/api)
- Rate limits as stated on the product page: **1,000 requests/second shared among all unauthenticated users** (throttled at peak), and an **introductory limit of 1 RPS on all endpoints with an API key**. Keys are requested via a form and emailed. The API is free; an "API License Agreement" governs use but its terms are not on the product page — [Semantic Scholar API](https://www.semanticscholar.org/product/api). Note: the shared-1000-rps vs keyed-1-rps framing is confusing as written; the practical meaning is that the unauthenticated pool is shared and unreliable, while a key gives a guaranteed dedicated 1 RPS.

**Peer-review / OA status**
- **Unpaywall REST API**: base URL `https://api.unpaywall.org/v2`, **no API key**, just an email in the request, **100,000 calls/day**; for larger work Unpaywall recommends the **full database snapshot** — [Unpaywall API](https://unpaywall.org/products/api); [Unpaywall API listing](https://apis.apievangelist.com/store/unpaywall/)
- For any DOI it returns **OA status (gold/hybrid/bronze/green), best OA location (publisher or repository), licence, version, and all free copies**, over **120M+ articles with Crossref DOIs** — [api-evangelist/unpaywall](https://github.com/api-evangelist/unpaywall)
- R client `roadoi` documents practical usage — [roadoi](https://docs.ropensci.org/roadoi/)

**Journal quality**
- **DOAJ public API is free**, with a rate limit of **2 requests/second on all routes**, allowing bursts of up to 5 queued requests per user; API keys are generally only for publishers submitting data. Current API version **4.0.1 (21 August 2025)** — [DOAJ API docs](https://doaj.org/docs/api/)
- **Licensing is split**: DOAJ **article metadata is CC0 1.0** (rights waived); **journal metadata is CC BY-SA 4.0** — [DOAJ blog: DOAJ's journal metadata](https://blog.doaj.org/2026/07/21/doajs-journal-metadata-an-original-and-open-metadata-set/); [DOAJ metadata FAQ](https://doaj.org/docs/faq/)
- Journal counts conflict across sources: an older figure cites "more than 14,000 journals" of which about **1,357 hold the DOAJ Seal**, while a third-party index states **10,625 journals as of September 2026** — [PMC table](https://pmc.ncbi.nlm.nih.gov/articles/PMC6174996/table/jdv15039-tbl-0003); [journalindexes.com, September 2026](https://journalindexes.com/doaj/). The second is a low-quality aggregator; neither was confirmed against DOAJ's own front page. Treat the count as unverified and query the API for a live number.

**Predatory journals**
- **Beall's List was maintained until January 2017**, when Jeffrey Beall took it down citing pressure from his employer; archived mirrors still circulate — [Wikipedia: Beall's List](https://en.wikipedia.org/wiki/Beall's_List)
- **Cabells** began working with Beall in 2015 and launched its own predatory-journal database on **15 June 2017**, renamed **Predatory Reports in June 2020**; it uses **74 structured criteria** but is **subscription-only** — [Wikipedia: Cabell Publishing](https://en.wikipedia.org/wiki/Cabell_Publishing); [Cabells blog](https://blog.cabells.com/tag/predatory-journals/)
- Cabells itself argues the stale Beall's List mirrors still damage publishers nearly a decade on — [Cabells: "Accusations frozen in time" (22 April 2026)](https://blog.cabells.com/2026/04/22/accusations-frozen-in-time-how-bealls-list-still-hurts-publishers-in-2026/)
- A **systematic review of predatory publishing lists** exists in the literature — [Predatory publishing lists: a systematic review (PMC12889366)](https://pmc.ncbi.nlm.nih.gov/articles/PMC12889366/); see also [Predatory Publishing: What Are the Alternatives to Beall's List? (Am J Med)](https://www.amjmed.com/article/S0002-9343(17)31196-8/fulltext)

### Inferences
- A practical, fully free academic-credibility check is: **DOI → Crossref (`update-to`/`relation` for retraction, `type` for preprint vs journal-article) → Unpaywall (OA status/version, where "submittedVersion" ≈ preprint) → OpenAlex (citation count, source, `is_in_doaj`) → DOAJ (journal indexed/Seal)**. All four are free with open licences; the total cost of this chain is bounded by OpenAlex's $1/day free budget, and singleton DOI lookups on OpenAlex are $0.
- **Prefer singleton lookups over search on OpenAlex**: the pricing table makes search 10× the cost of list/filter and infinitely more than a DOI lookup. A design that resolves identifiers first and searches only as a fallback is now cheaper by construction, not just faster.
- **Caching the Retraction Watch CSV locally is strictly better than per-DOI API calls** for a research tool: one daily Git pull gives the complete set with 20 fields, avoids rate limits entirely, and is CC BY 4.0 so it can be shipped.
- Predatory-journal screening has **no free structured source**. A reasonable free proxy is the inverse: treat DOAJ inclusion (and the DOAJ Seal) as positive evidence rather than trying to enumerate bad journals — combined with a check that the journal has a Crossref member DOI prefix at all.
- The stale-Beall's-mirror problem is a direct warning against shipping a cached blocklist: an engineer copying an archived Beall's List into a tool would be reproducing accusations that Cabells says are nearly a decade out of date.

### Gaps
- **Semantic Scholar's data licence** could not be established; the product page references an "API License Agreement" without stating terms. The bulk datasets' licence (believed to vary by corpus) is likewise unconfirmed here.
- **DOAJ quality-signal field names** (Seal flag, peer-review process type, APC) were not enumerated from the API docs page fetched; the schema would need to be read from the live `/api/search/journals` response.
- **Cabells Predatory Reports pricing** is not published.
- No current, authoritative count of DOAJ journals or of Seal holders was obtained.

## Domain-level heuristics used in practice

### Takeaway
The one solidly standardised heuristic is registrable-domain (eTLD+1) extraction via the Public Suffix List, which has mature libraries in every major language and is the correct primitive for "are these two citations actually independent?". Publication-date extraction and syndication detection are both empirical problems with published tooling and benchmarks but no standard.

### Cited Findings

**Registrable-domain grouping**
- The **Public Suffix List** is a community-maintained list of rules describing the domain suffixes under which independent organisations can register sites; the **registrable domain (eTLD+1)** is the main registrable part — [Wikipedia: Public Suffix List](https://en.wikipedia.org/wiki/Public_Suffix_List)
- PSL-backed libraries exist across languages: **Python** (`tldextract`, `publicsuffix2`), **JavaScript** (`psl`, `tldts`), **Java** (Guava `InternetDomainName`), **Go** (`golang.org/x/net/publicsuffix`, which compiles a copy of the publicsuffix.org database into the library), **Rust** (`publicsuffix2`), **R** (`pslr`), and a CLI (`etld1`) — [golang.org/x/net/publicsuffix](https://pkg.go.dev/golang.org/x/net/publicsuffix); [pslr on CRAN](https://cran.r-project.org/web/packages/pslr/index.html); [etld1](https://github.com/Firefishy/etld1/blob/main/README.md); [publicsuffix2 (Rust)](https://crates.io/crates/publicsuffix2)
- Implementations must handle the **ICANN vs private rule sections, wildcard rules, and Unicode/Punycode conversion** — [pslr](https://bart-turczynski.gitlab.io/pslr/)
- Browsers expose the same primitive: **`browser.publicSuffix`** in the WebExtensions API — [MDN publicSuffix](https://developer.mozilla.org/en-US/docs/Mozilla/Add-ons/WebExtensions/API/publicSuffix)

**Publication-date extraction**
- **Fundus**, a news scraper built for extraction quality, reports **99.89% precision and 97.69% F1** on content extraction, outperforming Trafilatura and BTE — [Fundus (arXiv 2403.15279)](https://arxiv.org/pdf/2403.15279). Note: these figures are for *content* extraction, not specifically dates.
- Documented failure modes for metadata extraction include **missing publication dates and author names** and **inconsistent date formats** (MM/DD/YYYY vs DD-MM-YYYY), which reduce context — [news scraping challenges](https://www.ottscrape.com/key-challenges-news-article-data-scraping.php)
- Learning-based crawling frameworks explicitly score candidate articles against goals including headline accuracy and publication date — [AI-driven web crawling for semantic extraction of news content (PMC12644869)](https://pmc.ncbi.nlm.nih.gov/articles/PMC12644869/)

**Syndication and content farms**
- Many local outlets publish articles that are fully or nearly duplicates of national wire copy (AP, Reuters), because wires sell stories for re-publication to many publishers — so search systems over news collections surface many duplicate copies — [Duplicate News Story Detection Revisited (Alonso, Microsoft Research)](https://www.microsoft.com/en-us/research/wp-content/uploads/2013/05/paper-1.pdf); [Springer version](https://link.springer.com/chapter/10.1007/978-3-642-45068-6_18)
- Syndicated stories typically keep the body while **locally replacing headlines and captions and adding locally-relevant content** — which is why headline matching fails and body near-duplicate detection works — [Duplicate News Story Detection Revisited](https://www.microsoft.com/en-us/research/wp-content/uploads/2013/05/paper-1.pdf)
- Method that works: near-duplicate detection improved by **weighting phrases in a sliding window by in-document term frequency and inverse document frequency of those phrases** — [Duplicate News Story Detection Revisited](https://www.microsoft.com/en-us/research/wp-content/uploads/2013/05/paper-1.pdf)
- **Tracking verbatim string occurrences across domains over time** enables study of cross-outlet reuse and narrative diffusion; **Infini-News** provides queryable access to 1.3 billion processed Common Crawl news articles for exactly this — [Infini-News (arXiv 2605.18337)](https://arxiv.org/pdf/2605.18337)
- Commercial media-monitoring systems implement this as a named feature — [Muck Rack duplicate article detection](https://help.muckrack.com/en/articles/6953341-duplicate-article-detection)
- For AI content farms specifically, the only maintained inventory found is NewsGuard's (3,749 sites, 16 languages, as of 23 June 2026), which is a commercial datastream — [NewsGuard AI Tracking Center](https://www.newsguardtech.com/special-reports/ai-tracking-center/)

### Inferences
- **eTLD+1 grouping is necessary but not sufficient for independence.** It correctly collapses `news.example.co.uk` and `blog.example.co.uk`, but it will treat every outlet in a chain (or every site republishing the same wire copy) as independent. Independence therefore needs *two* checks: eTLD+1 for same-owner-domain, plus body near-duplicate detection for same-content.
- The syndication literature implies a concrete rule for a research agent: **before counting N sources as N pieces of corroboration, shingle-hash the article bodies and collapse near-duplicates.** Three outlets carrying the same AP story is one source, and headline/caption localisation means title-based dedup will miss it.
- **Publication dates should be treated as low-confidence by default.** No source found offers a benchmark for date-extraction accuracy specifically, and the documented failure modes (missing dates, ambiguous DD/MM vs MM/DD) mean a date should carry a provenance tag (from `<meta>`/JSON-LD schema.org `datePublished` vs inferred from URL vs inferred from visible text) rather than being stored as a bare value.
- Crawling the PSL copy bundled in a library is a supply-chain freshness issue: `golang.org/x/net/publicsuffix` compiles a *copy* of the list in, so a long-lived tool needs a refresh policy or it will mis-group newly delegated suffixes.

### Gaps
- **No study was found measuring publication-date extraction accuracy specifically** (as opposed to article-body extraction). The Fundus figures are for content, and citing them as date accuracy would be wrong.
- No free, openly licensed **content-farm or AI-slop domain list** was found; NewsGuard's is commercial and the Iffy Index covers only fact-check failures, not AI generation.
- No benchmark was found for the precision/recall of near-duplicate syndication detection at web scale in a 2020s setting; the strongest methodological source (Alonso, Microsoft Research) predates the current era.
