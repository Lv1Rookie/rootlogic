## GPT Researcher: source selection, scraping, dedup, citation, credibility scoring, config

### Takeaway
GPT Researcher has exactly one credibility mechanism — `SourceCurator`, an LLM-as-judge pass gated behind `CURATE_SOURCES`, which defaults to `False` — and its prompt explicitly instructs the model to *err on the side of inclusion*. There is no domain allow/deny list in the shipped pipeline (`filter_urls` exists but is dead code referencing a config key that doesn't exist in the schema), dedup is URL-string-exact only, and citations are produced purely by prompt instruction with no post-hoc validation that a cited URL was actually retrieved.

### Cited Findings
- Source selection is embedding-relevance-driven, not credibility-driven: `ContextCompressor` in `gpt_researcher/context/compression.py` builds a `DocumentCompressorPipeline` of `RecursiveCharacterTextSplitter(chunk_size=1000, chunk_overlap=100)` + `EmbeddingsFilter(embeddings=..., similarity_threshold=self.similarity_threshold)` behind a `ContextualCompressionRetriever`. The only gate on a chunk entering context is cosine similarity to the query. — [compression.py](https://github.com/assafelovic/gpt-researcher/blob/master/gpt_researcher/context/compression.py)
- The threshold is read two different ways: `DEFAULT_CONFIG["SIMILARITY_THRESHOLD"] = 0.42` in `gpt_researcher/config/variables/default.py`, but `ContextCompressor.__init__` does `self.similarity_threshold = os.environ.get("SIMILARITY_THRESHOLD", 0.35)` — i.e. the compressor reads the env var directly and falls back to 0.35, not to the config's 0.42. — [default.py](https://github.com/assafelovic/gpt-researcher/blob/master/gpt_researcher/config/variables/default.py); [compression.py](https://github.com/assafelovic/gpt-researcher/blob/master/gpt_researcher/context/compression.py)
- There is a fast path that skips relevance filtering entirely: `ContextCompressor.async_get_context` computes `total_chars` over `raw_content` and, if `total_chars < COMPRESSION_THRESHOLD` (default `"8000"`) and `len(self.documents) <= max_results`, returns the documents directly with no embedding filter at all. — [compression.py](https://github.com/assafelovic/gpt-researcher/blob/master/gpt_researcher/context/compression.py)
- The credibility step is `SourceCurator.curate_sources()` in `gpt_researcher/skills/curator.py`. It is a single `create_chat_completion` call to `cfg.smart_llm_model` at `temperature=0.2, max_tokens=8000`, and it parses the reply with `json.loads(response)`. On any exception it logs "Error in curate_sources from LLM response" and **returns `source_data` unchanged** — a parse failure silently degrades to no curation while the UI has already streamed "⚖️ Evaluating and curating sources by credibility and relevance...". — [curator.py](https://github.com/assafelovic/gpt-researcher/blob/master/gpt_researcher/skills/curator.py)
- It is off by default: `"CURATE_SOURCES": False` in `DEFAULT_CONFIG`, typed as `CURATE_SOURCES: bool` in `gpt_researcher/config/variables/base.py`, and consumed at `gpt_researcher/skills/researcher.py:211` (`if self.researcher.cfg.curate_sources:` → `curated = await self.researcher.source_curator.curate_sources(research_data)`). — [default.py](https://github.com/assafelovic/gpt-researcher/blob/master/gpt_researcher/config/variables/default.py); [researcher.py](https://github.com/assafelovic/gpt-researcher/blob/master/gpt_researcher/skills/researcher.py)
- The curation prompt (`PromptFamily.curate_sources` in `gpt_researcher/prompts.py`, line ~319) biases hard toward inclusion. Verbatim rules include: "Relevance: Include sources directly or partially connected to the research query. Err on the side of inclusion."; "Credibility: Favor authoritative sources but retain others unless clearly untrustworthy."; "Objectivity: Retain sources with bias if they provide a unique or complementary perspective."; "Exclude sources only if they are entirely irrelevant, severely outdated, or unusable due to poor content quality." It also orders "DO NOT rewrite, summarize, or condense any source content." — [prompts.py](https://github.com/assafelovic/gpt-researcher/blob/master/gpt_researcher/prompts.py)
- The prompt's top-line optimisation target is data density, not trust: "while prioritizing the inclusion of relevant and high-quality information, especially sources containing statistics, numbers, or concrete data" and "Prioritize sources with statistics, numerical data, or verifiable facts." There is no numeric credibility score emitted — the model returns the same JSON list shape it was given. — [prompts.py](https://github.com/assafelovic/gpt-researcher/blob/master/gpt_researcher/prompts.py)
- **No working domain filter.** `gpt_researcher/actions/web_scraping.py` defines `async def filter_urls(urls, config)` which reads `config.excluded_domains`, but (a) `excluded_domains` appears in neither `BaseConfig` (`gpt_researcher/config/variables/base.py`) nor `DEFAULT_CONFIG`, and (b) a repo-wide grep finds `filter_urls` referenced only by its own definition and by `tests/test_filter_urls_guards.py` — it is never called from the research pipeline. Two sibling functions in the same file are stubs: `extract_main_content` returns the raw HTML with the comment "For now, we'll just return the raw HTML as a placeholder". — [web_scraping.py](https://github.com/assafelovic/gpt-researcher/blob/master/gpt_researcher/actions/web_scraping.py)
- Dedup is exact-URL set membership, nothing more. `gpt_researcher/skills/researcher.py` maintains `self.researcher.visited_urls` (a `set`): line 811 `if url not in self.researcher.visited_urls:` / 812 `.add(url)`, and line 1050 `new_urls = [url for url in urls if url not in self.researcher.visited_urls]` then 1060 `.update(new_urls)`. A code comment at line 108 notes `visited_urls` is deliberately not cleared between runs so subtopic researchers inherit the parent's URL set. There is no canonicalisation (no trailing-slash/UTM stripping), no content hashing, and no near-duplicate detection across mirrors or syndicated copies. — [researcher.py](https://github.com/assafelovic/gpt-researcher/blob/master/gpt_researcher/skills/researcher.py)
- Scraping quality control is DOM-tag heuristics only. `gpt_researcher/scraper/utils.py` has `clean_soup()` which `decompose()`s `script, style, footer, header, nav, menu, sidebar, svg` plus any tag whose class is in `disallowed_class_set = {"nav", "menu", "sidebar", "footer"}`, then `get_text_from_soup()` collapses whitespace. Nothing checks that the scrape succeeded meaningfully, that the page matches the search snippet, or that it is not a paywall/consent interstitial. — [scraper/utils.py](https://github.com/assafelovic/gpt-researcher/blob/master/gpt_researcher/scraper/utils.py)
- Citation is 100% prompt-enforced. `gpt_researcher/prompts.py` line 310: "Every substantive claim, figure or quote MUST carry an in-text citation to the source it came from. Do NOT cite sources that do not appear in the provided information." Line 309 fixes the format: "Use in-text citation references in {report_format} format and make it with markdown hyperlink placed at the end of the sentence or paragraph that references them like this: ([in-text citation](url))." A `reference_prompt` block (line ~277) adds "You MUST write all used source urls at the end of the report as references, and make sure to not add duplicated sources". No code parses the finished report to check the emitted URLs against `visited_urls`. — [prompts.py](https://github.com/assafelovic/gpt-researcher/blob/master/gpt_researcher/prompts.py)
- Config knobs that actually affect source breadth/quality: `RETRIEVER` (default `"tavily"`), `MAX_SEARCH_RESULTS_PER_QUERY: 5`, `MAX_ITERATIONS: 3`, `SIMILARITY_THRESHOLD: 0.42`, `CURATE_SOURCES: False`, `SCRAPER: "bs"`, `BROWSE_CHUNK_MAX_LENGTH: 8192`, `REPORT_FORMAT: "APA"`, `DEEP_RESEARCH_BREADTH: 3`, `DEEP_RESEARCH_DEPTH: 2`. Retriever choice is the closest thing to a source allow-list: `VALID_RETRIEVERS` in `gpt_researcher/retrievers/utils.py` includes scholarly backends `arxiv`, `semantic_scholar`, `pubmed_central` alongside general web ones, so pointing `RETRIEVER` at those is the de facto way to restrict source class. — [default.py](https://github.com/assafelovic/gpt-researcher/blob/master/gpt_researcher/config/variables/default.py); [retrievers/utils.py](https://github.com/assafelovic/gpt-researcher/blob/master/gpt_researcher/retrievers/utils.py)

### Inferences
- The default install of GPT Researcher performs **no** credibility assessment of any kind: `CURATE_SOURCES=False`, `filter_urls` unwired, no domain lists. Everything rests on the search provider's (usually Tavily's) own ranking plus embedding similarity.
- Even with `CURATE_SOURCES=True`, curation is post-scrape, so it can only shrink the context, not prevent low-trust pages from influencing intermediate summaries. PR #2090 (below) makes exactly this argument.
- The `json.loads` + broad `except` in `curate_sources` means curation failures are invisible in the report; an engineer copying this design should return a sentinel or re-raise rather than silently passing the uncurated list through.

### Gaps
- I could not find any documented, per-source numeric credibility score anywhere in gpt-researcher — the curator returns a filtered list, not scores. If the docs site claims otherwise, the code does not back it.

## Stanford STORM: grounding, conflicting sources, citation structure, published evaluation

### Takeaway
STORM is the only project in this set with a real, hardcoded **source deny-list** — 206 entries transcribed from Wikipedia's Perennial Sources page — and the most disciplined citation index bookkeeping (a repair pass that deletes out-of-range `[n]` markers and a placeholder-based renumbering scheme). It has no mechanism for conflicting sources: citation is an inline-`[n]` prompt instruction, and the paper's own evaluation measures organisation/coverage, not citation correctness. The repo has not been pushed to in ~12 months.

### Cited Findings
- The deny-list lives in `knowledge_storm/storm_wiki/modules/retriever.py` with an explicit provenance comment: "Internet source restrictions according to Wikipedia standard: https://en.wikipedia.org/wiki/Wikipedia:Reliable_sources/Perennial_sources". Three frozen sets: `GENERALLY_UNRELIABLE` (140 entries), `DEPRECATED` (47), `BLACKLISTED` (19). — [retriever.py](https://github.com/stanford-oval/storm/blob/main/knowledge_storm/storm_wiki/modules/retriever.py)
- Representative entries — `GENERALLY_UNRELIABLE`: `"arXiv"`, `"Amazon"`, `"Blogger"`, `"Ancestry.com"`, `"Anti-Defamation_League"`, `"YouTube"`, `"ZDNet"`. `DEPRECATED`: `"Daily_Mail"`, `"The_Epoch_Times"`, `"RT"`, `"Sputnik"`, `"Global_Times"`, `"Zero_Hedge"`, `"Newsmax"`, `"Crunchbase"`, `"Baidu_Baike"`. `BLACKLISTED`: `"Breitbart_News"`, `"InfoWars"`, `"Natural_News"`, `"Healthline"`, `"Famous_Birthdays"`, `"ZoomInfo"`. — [retriever.py](https://github.com/stanford-oval/storm/blob/main/knowledge_storm/storm_wiki/modules/retriever.py)
- The matcher is a crude substring test, which is the design's weak point:
  ```python
  def is_valid_wikipedia_source(url):
      parsed_url = urlparse(url)
      combined_set = GENERALLY_UNRELIABLE | DEPRECATED | BLACKLISTED
      for domain in combined_set:
          if domain in parsed_url.netloc:
              return False
      return True
  ```
  Entries are Wikipedia *article titles* (`"Daily_Mail"`, `"Centre_for_Research_on_Globalization"`), not domains, so they can never substring-match a real `netloc` like `dailymail.co.uk`. Only the handful of entries written as actual hostnames (`"bestgore.com"`, `"Examiner.com"`, `"Lulu.com"`, `"Ancestry.com"`, `"Last.fm"`, `"Lenta.ru"`) can fire. — [retriever.py](https://github.com/stanford-oval/storm/blob/main/knowledge_storm/storm_wiki/modules/retriever.py)
- Grounding is a `dspy.Signature` instruction, not a retrieval constraint. `WriteSection` in `knowledge_storm/storm_wiki/modules/article_generation.py`: "Write a Wikipedia section based on the collected information. ... 2. Use [1], [2], ..., [n] in line (for example, "The capital of the United States is Washington, D.C.[1][3]."). You DO NOT need to include a References or Sources section to list the sources at the end." Fields are `info` (prefix "The collected information:"), `topic`, `section`, and an `output` field whose prefix demands "proper inline citations". — [article_generation.py](https://github.com/stanford-oval/storm/blob/main/knowledge_storm/storm_wiki/modules/article_generation.py)
- Citation repair is real code, in `ArticleTextProcessing` (`knowledge_storm/utils.py`). `clean_up_citation(conv)` truncates each agent utterance at "References:" / "Sources:", strips "Answer:", computes `max_ref_num = max(int(x) for x in re.findall(r"\[(\d+)\]", ...))`, and **if `max_ref_num > len(turn.search_results)` it deletes the out-of-range markers** (`turn.agent_utterance.replace(f"[{i}]", "")`). This is the closest thing in any of these projects to a "did the model invent a citation number?" check. — [utils.py](https://github.com/stanford-oval/storm/blob/main/knowledge_storm/utils.py)
- Supporting helpers: `parse_citation_indices(s)` extracts `[\d+]` markers; `remove_uncompleted_sentences_with_citations(text)` normalises `[1, 2, 3]` → `[1][2][3]`, deduplicates and sorts each group, and truncates to the last complete sentence-plus-citation; `update_citation_index(s, citation_map)` renumbers via a two-pass `__PLACEHOLDER_{n}__` substitution so that remapping 1→3 and 3→1 doesn't collide. — [utils.py](https://github.com/stanford-oval/storm/blob/main/knowledge_storm/utils.py)
- That repair logic has been a persistent bug source. Four separate merged PRs fix it: #421 "Fix discarded str.replace() results in citation cleanup" (2026-04-08), #428 "Fix clean_up_citation removing the last valid reference" (2026-04-15), #442 "assign result of str.replace() when stripping [-1] citation markers" (2026-05-06), #443 "start invalid-citation removal at len(search_results)+1" (2026-05-17), plus #494 "Guard None agent utterances in clean_up_citation" (2026-07-16). — [storm PRs](https://github.com/stanford-oval/storm/pull/443)
- Known-issue report, still open: issue #168 "[BUG] Inconsistent Citations Generation in Storm" (opened 2024-09-12, still open): "STORM does not consistently generate citations. Labels like "[1]" and "[2]" appear in the text, indicating where citations should be, but no corresponding references are included. Besides, while some citations are correct, others contain invalid links." — [storm#168](https://github.com/stanford-oval/storm/issues/168)
- README caveat, verbatim: "While the system cannot produce publication-ready articles that often require a significant number of edits, experienced Wikipedia editors have found it helpful in their pre-writing stage." — [storm README](https://github.com/stanford-oval/storm/blob/main/README.md)
- Published evaluation (NAACL 2024 paper, arXiv:2402.14207) is built on **FreshWiki**, "a collection of 100 high-quality Wikipedia articles focusing on the most-edited pages from February 2022 to September 2023", explicitly constructed to mitigate data contamination (the construction pipeline is archived at the `NAACL-2024-code-backup` branch). The headline results are human: experienced Wikipedia editors rated STORM articles +25% absolute on organisation and +10% on breadth of coverage versus an outline-driven RAG baseline. — [STORM paper abstract](https://arxiv.org/abs/2402.14207); [storm README](https://github.com/stanford-oval/storm/blob/main/README.md)
- The paper's stated remaining challenges include **source bias transfer** and **over-association of unrelated facts** — i.e. the authors name source-trust as unsolved rather than claim to solve it. — [STORM paper abstract](https://arxiv.org/abs/2402.14207)
- There is prior art for citation-level evaluation in the repo's history — PR #16 "Update citation_quality.py" (2024-04-15) — but no `citation_quality*` file and no `eval/` directory exist at HEAD today. — [storm PR #16](https://github.com/stanford-oval/storm/pull/16)

### Inferences
- STORM's deny-list is the right *idea* implemented with the wrong *key*: an engineer stealing it should re-key the sets by registrable domain (Wikipedia's Perennial Sources table has the domains) and match on eTLD+1 rather than substring-in-netloc, otherwise ~95% of the 206 entries are inert.
- `clean_up_citation`'s out-of-range deletion is a genuinely portable pattern: it gives you a cheap, deterministic guarantee that no `[n]` survives that doesn't index a real retrieved document. It does *not* check that document `[n]` supports the sentence — only that `n` exists.
- STORM handles conflicting sources only implicitly, via the multi-perspective question-asking stage (personas) producing a wider `information_table`; nothing in the code detects or adjudicates contradiction.

### Gaps
- The arXiv abstract page did not expose the paper's automatic metrics section; I could not confirm from a primary source whether the paper reports ROUGE / entity-recall / heading-soft-recall figures, and I did not want to assert numbers I hadn't read. Anyone extending this should read the PDF §4.
- No evidence STORM evaluates citation precision/recall anywhere at HEAD.

## Hugging Face open_deep_research and LangChain/LangGraph open_deep_research: what verification?

### Takeaway
Effectively none in either. HF's `open_deep_research` is a GAIA benchmark agent that emits a short final answer with no citation apparatus at all; LangChain's `open_deep_research` enforces citations purely by prompt text, and the word "verification" in its prompts refers to a *clarification acknowledgement message to the user*, not to checking sources.

### Cited Findings
- HF open_deep_research lives at `examples/open_deep_research/` inside smolagents (files: `run.py`, `run_gaia.py`, `app.py`, `analysis.ipynb`, `scripts/`). It builds a `ToolCallingAgent` named `search_agent` with `WEB_TOOLS = [GoogleSearchTool(provider="serper"), VisitTool(browser), PageUpTool, PageDownTool, FinderTool, FindNextTool, ArchiveSearchTool(browser), TextInspectorTool(model, text_limit)]` over a `SimpleTextBrowser` with `viewport_size: 1024 * 5` and `text_limit = 100000`, `max_steps=20`, `planning_interval=4`. There is no citation tool, no source list, no dedup step and no verification step anywhere in `run.py`. — [run.py](https://github.com/huggingface/smolagents/blob/main/examples/open_deep_research/run.py)
- Its only quality metric is task accuracy: README states "This agent achieves **55% pass@1** on the GAIA validation set, compared to **67%** for the original Deep Research." GAIA answers are short exact strings, so citation quality is out of scope by construction. — [HF ODR README](https://github.com/huggingface/smolagents/blob/main/examples/open_deep_research/README.md)
- The one trust-adjacent tool is `ArchiveSearchTool`, which lets the agent fetch a Wayback Machine snapshot of a URL at a date — useful for temporal grounding, not for credibility. — [run.py](https://github.com/huggingface/smolagents/blob/main/examples/open_deep_research/run.py)
- LangChain ODR's `src/open_deep_research/prompts.py` uses "verification" only in the clarify-with-user JSON schema: `"verification": "<verification message that we will start research>"` and "For the verification message when no clarification is needed". It is a UX acknowledgement string, not source verification. — [prompts.py](https://github.com/langchain-ai/open_deep_research/blob/main/src/open_deep_research/prompts.py)
- Its `<Citation Rules>` block (appearing twice — in `compress_research_system_prompt` and in the final-report prompt) is entirely instructional: "Assign each unique URL a single citation number in your text"; "End with ### Sources that lists each source with corresponding numbers"; "IMPORTANT: Number sources sequentially without gaps (1,2,3,4...) in the final list regardless of which sources you choose"; "- Citations are extremely important. Make sure to include these, and pay a lot of attention to getting these right. Users will often use these citations to look into more information." No code validates any of it. — [prompts.py](https://github.com/langchain-ai/open_deep_research/blob/main/src/open_deep_research/prompts.py)
- The compression stage's guardrail is anti-loss, not anti-fabrication: "It is expected that you repeat key information verbatim"; "It's really important not to lose any sources. A later LLM will be used to merge this report with others, so having all of the sources is critical"; "Critical Reminder: It is extremely important that any information that is even remotely relevant to the user's research topic is preserved verbatim (e.g. don't rewrite it, don't summarize it, don't paraphrase it)." The closest thing to corroboration handling is a single instruction: "if three sources all say "X", you could say "These three sources all stated X"." — [prompts.py](https://github.com/langchain-ai/open_deep_research/blob/main/src/open_deep_research/prompts.py)
- Legacy implementation (`src/legacy/prompts.py`, still shipped) is no stronger — it asks the model to self-check formatting only: "3. Verify that sources are numbered sequentially (1,2,3...) without any gaps", plus soft quality language ("At least 3 high-quality sources with diverse perspectives", "Keep important quotes from credible sources or experts"). — [legacy/prompts.py](https://github.com/langchain-ai/open_deep_research/blob/main/src/legacy/prompts.py)
- Known citation issues are formatting-level: open issue #232 "Inconsistency between Output Format and Citation Rules for the Sources section in `compress_research_system_prompt`" (2026-01-22), closed #34 "Inline citations" (2025-02-28), closed #64 "Refactor report for coherence and reference consolidation" (2025-03-18), fixed by PR #301 "fix(prompts): align compressed sources format" (2026-08-03). — [open_deep_research#232](https://github.com/langchain-ai/open_deep_research/issues/232)

### Inferences
- LangChain ODR's architecture actively *increases* citation risk: research is compressed per-subagent and then merged by a second LLM, so citation numbers are reassigned at least twice by models with no access to the original retrieval indices. The repeated, emphatic prompt language about citations is a tell that this is a known soft spot.
- Neither project is a useful source of verification ideas to steal; they are useful as the control group showing how much of the field ships citation-by-prompt only.

### Gaps
- I did not audit LangChain ODR's `utils.py` / `deep_researcher.py` line-by-line for a post-hoc URL validator; the prompt-side evidence plus the issue tracker strongly suggests none exists, but I am reporting this as not-exhaustively-verified.

## Local Deep Research: what the "verification"/"fact-check" step actually does

### Takeaway
LDR is by far the most elaborate — and the only project here with a real, data-backed **domain/venue credibility database** (`journal_quality`, built from OpenAlex + DOAJ + predatory-journal lists, with a numeric 1–10 score and a configurable exclusion threshold), a **verbatim-quote-only extraction prompt**, and a **URL-vs-snippet consistency check**. But its LLM "fact-checking" step is shallow and off by default, and one of its shipped citation handlers explicitly instructs the model to never say "I don't know".

### Cited Findings
- **Journal/venue credibility scoring.** `src/local_deep_research/journal_quality/scoring.py` exposes `derive_quality_score(*, h_index, quartile, is_in_doaj, is_predatory, source_type) -> Optional[int]`, documented as "Derive a 1–10 quality score from bibliometric data", with inputs "in order of preference": SJR-style `quartile` (Q1–Q4) as "the strongest single signal — this is what librarians and reviewers use", then `h_index` standalone, then `is_in_doaj` as "the weakest fall-through signal". Predatory venues short-circuit: `if is_predatory and not is_in_doaj: return JOURNAL_QUALITY_PREDATORY  # Auto-remove threshold`. Preprint repositories (arXiv, bioRxiv, SSRN, PsyArXiv) are separately down-weighted as "not peer-reviewed". — [scoring.py](https://github.com/LearningCircuit/local-deep-research/blob/main/src/local_deep_research/journal_quality/scoring.py)
- The thresholds are named constants (`JOURNAL_HINDEX_ELITE/STRONG/VERY_GOOD/GOOD/ACCEPTABLE`, `JOURNAL_QUALITY_*`, `INSTITUTION_HINDEX_HIGH/TOP`, `CONFERENCE_QUALITY_DEFAULT`, `REPOSITORY_QUALITY_DEFAULT`, `DOAJ_QUALITY_LISTED`) and the docstring shows the calibration data: "Nature h-index: 1,442 / PLOS ONE h-index: 467 / Only 3 journals globally have h-index > 1,000". It also documents a known flaw: "h-index has field-dependent bias (mathematics journals have naturally lower h-index than biomedical journals). These thresholds are general-purpose; field-specific normalization is not yet implemented." And a deliberate removal: the DOAJ Seal input was dropped because "DOAJ retired the Seal in April 2025". — [scoring.py](https://github.com/LearningCircuit/local-deep-research/blob/main/src/local_deep_research/journal_quality/scoring.py)
- Data sources are pluggable files under `src/local_deep_research/journal_quality/data_sources/`: `openalex.py`, `doaj.py`, `predatory.py`, `institutions.py`, `jabref.py`, `_openalex_common.py`, over a `base.py` interface; `db.py` builds a local `journal_quality.db` with "cross-referenced DOAJ + predatory flags". — [journal_quality/db.py](https://github.com/LearningCircuit/local-deep-research/blob/main/src/local_deep_research/journal_quality/db.py)
- The runtime gate is `src/local_deep_research/advanced_search_system/filters/journal_reputation_filter.py`, which imports `get_db as get_journal_data_manager` and `normalize_name`, calls `dm.derive_quality_score(...)` at several tiers (journal match, `is_in_doaj=True` fallback, institution-only fallback, `source_type="conference"`), and stamps each result with `result["journal_quality"]`, `result["journal_quality_source"]`, or the sentinels `QUALITY_PENDING` / `QUALITY_PREPRINT`. — [journal_reputation_filter.py](https://github.com/LearningCircuit/local-deep-research/blob/main/src/local_deep_research/advanced_search_system/filters/journal_reputation_filter.py)
- Exposed settings (`src/local_deep_research/defaults/default_settings.json`), with shipped defaults: `search.journal_reputation.threshold = 2` ("Minimum journal quality score required for academic results. Sources below this threshold are excluded when the filter is [enabled]"); `search.journal_reputation.enable_llm_scoring = False` ("Enable Tier 4 LLM journal scoring via SearXNG. When disabled (default), only bundled data (OpenAlex, DOAJ, predatory lists) [is used]"); `search.journal_reputation.exclude_non_published = False`; `search.journal_reputation.max_context = 3000`; `search.journal_reputation.reanalysis_period = 365`; and per-engine `search.engine.web.arxiv.journal_reputation.enabled = True`. — [default_settings.json](https://github.com/LearningCircuit/local-deep-research/blob/main/src/local_deep_research/defaults/default_settings.json)
- **Verbatim-quote extraction.** `src/local_deep_research/advanced_search_system/tools/fetch/prompts.py` defines `_ROLE` + `_RULES` shared by `SUMMARY_FOCUS_PROMPT` and `SUMMARY_FOCUS_QUERY_PROMPT`. `_ROLE`: "you are an extractor, NOT an answerer. Do not interpret, conclude, or compose. Just pull the relevant raw text out of the page." `_RULES`: "Output ONLY verbatim quotes from the page. Copy numbers, names, dates, and proper nouns exactly as written — never paraphrase facts."; "One quote per line."; "Omit navigation, ads, cookie/subscription banners, related-article lists, author bios, comments"; "If nothing on the page helps, reply with exactly: NOT RELEVANT"; "Maximum 1500 characters. Quality over quantity — fewer precise quotes beat many borderline ones." A code comment explains the role-framing is empirical: "small local models (qwen3, gpt-oss) calibrate measurably better when told what's downstream of their output." — [fetch/prompts.py](https://github.com/LearningCircuit/local-deep-research/blob/main/src/local_deep_research/advanced_search_system/tools/fetch/prompts.py)
- **URL-vs-snippet consistency check.** Setting `search.quality_check_urls = True` (on by default): "Validate that fetched webpage content matches the search result's title and snippet. Helps filter out broken links or mismatched content." Implemented in `src/local_deep_research/web_search_engines/engines/full_search.py` via `FullSearchResults._url_quality_prompt(results, query)`, which asks an LLM to evaluate URLs for "1. Timeliness (today: {current_time}) 2. Factual accuracy (cross-reference major claims) 3. Source reliability (prefer official company websites, established news outlets) 4. Direct relevance to query" and to "Return a JSON array of indices (0-based) for sources that meet ALL criteria." A companion constant `QUALITY_CHECK_DDG_URLS` lives in `config/search_config.py`. — [full_search.py](https://github.com/LearningCircuit/local-deep-research/blob/main/src/local_deep_research/web_search_engines/engines/full_search.py); [default_settings.json](https://github.com/LearningCircuit/local-deep-research/blob/main/src/local_deep_research/defaults/default_settings.json)
- **The "fact-check" step itself is one extra LLM call, off by default.** `general.enable_fact_checking = False` ("Enable LLM-based fact verification for research findings. Adds additional validation pass to check claims against sources"), read by `BaseCitationHandler.is_fact_checking_enabled()` at `citation_handlers/base_citation_handler.py:299` via `self.get_setting("general.enable_fact_checking", False)`. In `standard_citation_handler.py` the gated prompt is: "Analyze these sources for factual consistency: 1. Cross-reference major claims between sources 2. Identify and flag any contradictions 3. Verify basic facts (dates, company names, ownership) 4. Note when sources disagree ... Return any inconsistencies or conflicts found." Its output is then spliced into the answer prompt as free text — "Reflect information from sources critically based on: {fact_check_response}. Never invent sources." Nothing acts on it programmatically; no claim is blocked, no confidence is recorded. — [standard_citation_handler.py](https://github.com/LearningCircuit/local-deep-research/blob/main/src/local_deep_research/citation_handlers/standard_citation_handler.py)
- `StandardCitationHandler` does have a genuine refusal path: `analyze_initial` returns `self._no_sources_response(query)` when `not documents`, and `analyze_followup` refuses when `not documents and not (previous_knowledge or "").strip()`, with the code comment "With previous knowledge present the LLM can still cite prior sources legitimately; with neither, refuse to synthesize." Its prompt also bans URL invention: "Never make up sources. Never write or create urls." — [standard_citation_handler.py](https://github.com/LearningCircuit/local-deep-research/blob/main/src/local_deep_research/citation_handlers/standard_citation_handler.py)
- **Counter-example worth flagging.** `citation_handlers/forced_answer_citation_handler.py` ("optimized for BrowseComp-style questions. Always provides a specific answer, never returns 'cannot determine'") instructs: "NEVER say 'I cannot determine' or 'insufficient information'"; "If unsure between options, choose the MOST LIKELY based on evidence"; and closes with "Remember: A wrong answer is better than no answer for this task." It also runs the same shallow fact-check prompt but asks it to "Identify the most frequently mentioned answer" — majority-vote-as-truth. — [forced_answer_citation_handler.py](https://github.com/LearningCircuit/local-deep-research/blob/main/src/local_deep_research/citation_handlers/forced_answer_citation_handler.py)
- `citation_handlers/precision_extraction_handler.py` adds deterministic regexes over model output — `full_name`, `year` (`\b(19\d{2}|20\d{2})\b`), `number`, `dimension` (value + unit), `score`, `percentage`, `location` — used by `_identify_question_type()` and `_apply_precision_extraction()` to re-extract an exact answer from the formatted sources. This is answer-shape enforcement, not claim verification. — [precision_extraction_handler.py](https://github.com/LearningCircuit/local-deep-research/blob/main/src/local_deep_research/citation_handlers/precision_extraction_handler.py)
- Other relevant machinery: `advanced_search_system/filters/cross_engine_filter.py` (`CrossEngineFilter`, LLM relevance rerank + reindex across engines, params `max_results`, `default_reorder`, `default_reindex`); `utilities/citation_normalizer.py` (`normalize_citation`, `normalize_issn`, `_extract_doi`, `_extract_arxiv_id`, `_build_csl_json` — emits CSL-JSON, i.e. citations become structured records, not just URLs); `text_optimization/citation_formatter.py` driven by `report.citation_format = number_hyperlinks` (options include domain-based `[arxiv.org]` and "smart domain numbering"); `domain_classifier/`. — [LDR src tree](https://github.com/LearningCircuit/local-deep-research/tree/main/src/local_deep_research)

### Inferences
- LDR is the best place to steal from, but the pieces are unevenly wired: the strongest components (journal_quality DB, verbatim extraction prompt) are deterministic and data-backed; the component actually *called* "fact checking" is the weakest (one unconstrained LLM call whose output is pasted into another prompt) and ships disabled.
- The `journal_quality` design generalises well beyond academia: a local SQLite of venue→score built from public bibliometric dumps, a `threshold` setting, and per-engine enable flags is a clean template for a web-domain credibility table.
- The coexistence of `StandardCitationHandler` (refuses without sources) and `ForcedAnswerCitationHandler` ("a wrong answer is better than no answer") in the same codebase is a direct illustration of benchmark-driven pressure against verification — worth calling out in the report.

### Gaps
- I did not trace whether `search.quality_check_urls` is applied to all engines or only the DuckDuckGo/full-search path (the constant name `QUALITY_CHECK_DDG_URLS` hints at the latter).
- LDR has a `benchmarks/` package but I did not extract its reported citation-accuracy numbers; I found no published paper for LDR.

## Cross-cutting: who implements per-claim verification, verbatim-quote checking, allow/deny lists, credibility ratings, corroboration

### Takeaway
Across all five projects, **nobody implements per-claim verification against fetched page text**. Deny-lists exist in exactly one project (STORM, with a matching bug that makes most entries inert); numeric credibility ratings in exactly one (LDR, for academic venues only); verbatim-quote *instruction* in one (LDR) with no programmatic check that the quote appears in the page; and cross-source corroboration only as prompt text ("cross-reference major claims") with no code that counts agreeing sources.

### Cited Findings
- **Per-claim verification against page text:** none found. The nearest thing is STORM's `clean_up_citation`, which verifies only that a citation *index* is within `len(turn.search_results)` — never that the cited document supports the sentence. — [utils.py](https://github.com/stanford-oval/storm/blob/main/knowledge_storm/utils.py)
- **Verbatim-quote checking:** LDR *instructs* verbatim extraction ("Output ONLY verbatim quotes from the page ... never paraphrase facts") but a grep across gpt-researcher, STORM, LDR and LangChain ODR for string-containment verification of a quote against source text returns nothing — no `if quote in page_text` style assertion anywhere. — [fetch/prompts.py](https://github.com/LearningCircuit/local-deep-research/blob/main/src/local_deep_research/advanced_search_system/tools/fetch/prompts.py)
- **Allow/deny lists:** STORM's three sets (206 entries) via `is_valid_wikipedia_source`; gpt-researcher's `filter_urls`/`excluded_domains` is dead code with no config schema entry. LDR's equivalent is the `journal_quality` predatory-publisher list (`data_sources/predatory.py`) plus `search.journal_reputation.threshold`. — [retriever.py](https://github.com/stanford-oval/storm/blob/main/knowledge_storm/storm_wiki/modules/retriever.py); [web_scraping.py](https://github.com/assafelovic/gpt-researcher/blob/master/gpt_researcher/actions/web_scraping.py)
- **Domain credibility ratings:** only LDR's 1–10 `derive_quality_score`, and only for journals/conferences/institutions/repositories — there is no general-web domain rating in any of these projects. — [scoring.py](https://github.com/LearningCircuit/local-deep-research/blob/main/src/local_deep_research/journal_quality/scoring.py)
- **Cross-source corroboration:** exists only as prompt language — LDR's "Cross-reference major claims between sources" / "Identify the most frequently mentioned answer" (`standard_citation_handler.py`, `forced_answer_citation_handler.py`), and LangChain ODR's "if three sources all say "X", you could say "These three sources all stated X"". No project computes an agreement count, an independence check, or a confidence score. — [standard_citation_handler.py](https://github.com/LearningCircuit/local-deep-research/blob/main/src/local_deep_research/citation_handlers/standard_citation_handler.py); [LangChain ODR prompts.py](https://github.com/langchain-ai/open_deep_research/blob/main/src/open_deep_research/prompts.py)
- **The best articulation of the architectural problem comes from a contributor, not a maintainer.** gpt-researcher PR #2090 "feat: two-stage source filtering to exclude unwanted sources" (open since 2026-08-29, 0 comments) argues: "The existing `SourceCurator` ranks sources by relevance and credibility, but it operates **after** all scraped content has already been ingested into the research context ... Curating them afterward cannot undo that influence." And on fact-checking specifically: "post-hoc curation isn't a quality trade-off — it invalidates the verification itself. A fact-check is only meaningful when the evidence comes from sources **independent** of the claim's origin — and nothing between scraping and report generation reads content critically: Summaries (LLM) and context selection (embeddings) — Claimant pages are chunked, embedded, and summarized exactly like independent ones; only similarity matters, never trustworthiness. Contaminated citations — Derivative content (press releases, articles quoting the claimant) is indistinguishable from independent coverage". — [gpt-researcher#2090](https://github.com/assafelovic/gpt-researcher/pull/2090)

### Inferences
- The field's de facto verification stack is: (1) trust the search API's ranking, (2) embedding-similarity filter, (3) tell the model to cite, (4) occasionally renumber. Steps that would constitute verification — entailment checking a claim against its cited span, string-matching quotes, counting independent corroborating domains — are absent everywhere I looked.
- PR #2090's "independence" framing is the single most useful design idea surfaced by this research: filter at the *search and scrape boundaries* so excluded sources never enter any context window, rather than curating after ingestion.
- An engineer building this properly can assemble a credible design from three existing pieces: STORM's index-bounds citation repair (fixed to match on eTLD+1), LDR's `derive_quality_score` + threshold pattern generalised to web domains, and LDR's verbatim-extraction prompt — then add the missing layer (quote-in-page string check + per-claim entailment) that no project has.

### Gaps
- I found no open-source research agent in this survey implementing NLI/entailment-based claim verification against fetched text. That may exist in less prominent repos; my survey covered the five named projects only.

## Reported weaknesses and known issues around citation accuracy

### Takeaway
Each project's issue tracker tells the same story: citation problems are treated as *formatting and numbering* bugs, not truth bugs, and hallucination evaluation shows up as contributor PRs that stall rather than shipped features.

### Cited Findings
- **STORM:** issue #168 (open since 2024-09-12) reports missing references behind live `[1]`/`[2]` markers and "some generated links are invalid". Five separate PRs (#421, #428, #442, #443, #494) were needed to make `clean_up_citation` correct — off-by-one, discarded `str.replace()` return values, removal of the last valid reference, and `None` utterances. — [storm#168](https://github.com/stanford-oval/storm/issues/168); [storm#443](https://github.com/stanford-oval/storm/pull/443)
- **STORM (paper-level):** the authors name "source bias transfer" and "over-association of unrelated facts" as challenges surfaced by expert feedback, and the README concedes the system "cannot produce publication-ready articles". — [STORM paper](https://arxiv.org/abs/2402.14207); [storm README](https://github.com/stanford-oval/storm/blob/main/README.md)
- **GPT Researcher:** only 5 issues/PRs mention hallucination at all. PR #1439 "feat: Add Hallucination Evaluation for GPTResearcher + `judges` library" (2025-06-21) proposed an `evals/hallucination_eval` directory that "assesses the factual accuracy of GPTResearcher's reports by comparing them against the context, providing confidence scores and detailed reasoning" — **closed, not merged**. PR #1821 "Add quality_eval: ground-truth-free report quality evaluation" (2026-06-26) and issue #1690 "Implement DeepResearchGym-style evaluations" (2026-03-22) both remain open. PR #1809 "feat: Add FactChecker and Visualizer Agents to Multi-Agent Workflow" (2026-06-15) is closed. — [gpt-researcher#1439](https://github.com/assafelovic/gpt-researcher/pull/1439); [gpt-researcher#1690](https://github.com/assafelovic/gpt-researcher/issues/1690)
- **GPT Researcher:** the repo's own `ISSUE_BACKLOG.md` records that curation has been crash-prone: issue #1415 was "Source verification failed: 'PromptFamily' object has no attribute 'curate_soures'" (a typo in the method name), and #1279 was an `AttributeError: 'list' object has no attribute 'split'` in `count_words` that "crashed on list input when CURATE_SOURCES=true". Both concern the only credibility feature in the product. — [gpt-researcher ISSUE_BACKLOG.md](https://github.com/assafelovic/gpt-researcher/blob/master/ISSUE_BACKLOG.md)
- **LangChain ODR:** citation issues are all structural — #232 (open) on Output Format vs Citation Rules inconsistency in `compress_research_system_prompt`, #34 "Inline citations", #64 "Refactor report for coherence and reference consolidation", PR #301 aligning the compressed sources format. Nothing about citations being wrong. — [open_deep_research#232](https://github.com/langchain-ai/open_deep_research/issues/232)
- **HF open_deep_research:** no citation issues because there are no citations; the README's honest framing is that it is a GAIA replication attempt at 55% vs OpenAI's 67%. — [HF ODR README](https://github.com/huggingface/smolagents/blob/main/examples/open_deep_research/README.md)
- **LDR:** the self-documented weakness is in code comments rather than issues — `scoring.py` states h-index thresholds carry "field-dependent bias" and "field-specific normalization is not yet implemented", and the DOAJ Seal tier "could never be earned again and only ever fired on stale pre-2025 data" before removal. — [scoring.py](https://github.com/LearningCircuit/local-deep-research/blob/main/src/local_deep_research/journal_quality/scoring.py)

### Inferences
- The rejection of gpt-researcher PR #1439 and the year-long dormancy of #1690/#1821 suggest citation-accuracy evaluation has no maintainer owner in the most popular of these projects — a meaningful signal for anyone deciding whether to build on it versus fork.
- STORM's five bug-fix PRs against ~40 lines of citation cleanup are a good cautionary data point: even the *trivial* verification layer (index bounds) is hard to get right, which partly explains why nobody has attempted the hard one.

### Gaps
- I did not find any project publishing measured citation precision/recall for its own output. If such numbers exist for these tools they are not in the repos or READMEs I read.
